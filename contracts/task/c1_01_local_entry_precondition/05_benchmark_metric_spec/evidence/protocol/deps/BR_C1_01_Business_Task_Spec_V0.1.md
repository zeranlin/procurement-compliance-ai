## 1 任务结论与适用范围

本任务识别政府采购文件中的**一个可独立判断的要求**，是否把供应商的注册地、所在地与采购人之间的距离、投标／评审前已经设立特定地区分支机构，或**投标时必须承诺中标后在指定地区设立售后服务机构**，作为资格、实质响应或评审条件。最后一种情形的机构实际设立时间可以在中标后，但投标时承担该地域实体义务已经成为竞争条件。输出是供后续核查的**候选线索**、原文证据及不确定性，不是“违法／合法”结论。来源工作指引在项目蓝图中所摘的第1类第1项表现形式为：“采购文件设置供应商注册地、所在地距采购人的距离、在某行政区域内设立分支机构等不合理的资格条件、评审因素。”本版新增的承诺情形依据中国政府采购网刊载的[财政部典型案例 1](https://www.ccgp.gov.cn/aljd/202512/t20251202_25830205.htm)纳入内部候选识别边界，不把它冒称为工作指引的逐字枚举。

2026 年财政部等部门的专项整治通知将采购文件中的差别歧视条款、以供应商注册地等不合理条件区别对待供应商列为工作重点，并将线索梳理、核实与处理处罚置于不同阶段。这支持本 Demo 将候选识别与最终认定分离；本任务并不独立判断某一具体例外的法律适用。[财政部等关于开展2026年专项整治工作的通知](https://www.mof.gov.cn/gp/xxgkml/gks/202606/t20260611_3991484.htm)。

### 1.1 纳入

仅评估**采购文件对供应商的要求**，且满足下列两项的候选识别：

1. **地域属性或定点设机构义务**：注册／登记地、供应商既有办公或经营地点到采购人的距离、投标前已存在的特定地区分公司／分支机构，或者投标时必须承诺中标后在指定行政区域设立售后服务机构；
2. **竞争作用**：将该属性或设机构承诺用于资格、实质响应、废标／无效投标、评分加减分、排名或优先选择，并且条款本身未明确属于经核实的特殊法定情形。

“不合理”在本任务中是**筛查方向**：模型识别身份代理限制形成的候选线索，后续人员才核查履约必要性、可替代措施、适用法规、例外和完整证据。明显属于同类限制的表述，即使未提供完整法律材料，仍可标 `MATCH`；其法律评价保持开放。

### 1.2 排除与移交

- 单纯规定服务响应时效、驻场服务、备件到达时限、项目所在地履约点，允许中标后自行选择人员、合作方或服务机制，且**不要求在指定区域设立实体机构**；
- 描述采购人地址、项目实施地点、交货地点、报价人所在地事实，未施加准入或评分后果；
- 所有制、组织形式、规模、业绩、品牌等其他表现形式，以及其他类／其他项；即使值得审查，也不贴本项 `MATCH`；
- 行政处理处罚、法源适用、法规冲突及例外裁决、采购文件整体“合规／不合规”结论、完整 7 类 22 项覆盖，移交后续业务和法律审查。

## 2 核心心智模型与强制不变量

| 心智模型 | 在 C1-01 的可执行含义 | 必须通过的边界检查 |
|---|---|---|
| `Task != FinalViolationJudgment` | `MATCH` 仅为本项候选；不得输出违法、处罚、法定责任的确定结论。 | 输出只含三分类和证据；拒绝法律定论字段。 |
| `KeywordMatch != ItemMatch` | “本地／分公司／距离”不能单独触发，须结合对象、时间和竞争作用。 | 只含关键词的项目地址或履约响应样例不误报。 |
| `LocalServiceNeed != LocalEntityPrecondition` | 结果型服务能力与地域实体义务不同；后者可表现为投标时要求已有机构，或强制承诺中标后在当地设机构。 | 把“已有本市分公司／须承诺中标后设本地售后机构”改成“不限方式达到响应时效”，标签应翻转。 |
| `Clause != Requirement` | 一段可拆成若干原子要求，分别出结果；上下文可以共享。 | 同一条款含资格门槛和履约承诺时产出两条，不用单一总标签覆盖。 |
| `CollectedCase != TrainingCase` | 原始收集、证据核验、内部复核和数据验收是不同阶段。 | 未证实出处或争议未决案例不可直接作为训练标签。 |
| `InternalSilver != Gold` | 内部标注供 Demo 使用，不冒充独立专家裁决的正式真值。 | 每条样本保留 `label_authority=INTERNAL_SILVER`。 |
| `TrainingSet != BenchmarkSet` | 训练、开发与盲测按项目／模板家族隔离，盲测真值由测试组持有。 | 反事实对同组；算法组不能读取 blind gold。 |

跨团队的完整契约还要求：**字段语义 + 业务例子 + 心智模型 + 不变量 + 失败场景 + 可执行测试**；因此以下规则同时规定“何时命中”“如何弃权”“证据在哪里”和“怎样验收”。

## 3 判定对象和上下文

**分析单元是 Requirement**：一个可单独成立、可以单独标记的供应商义务或评分条件。上游将项目→文档→版本→章节→条款→要求→证据串联；若条款含多个条件，先拆解再分类。例如“投标人须在本市注册，且中标后两小时内响应”拆成注册地门槛（`MATCH`）和响应时效承诺（`NO_MATCH`）。若两者因句法不能可靠分开，保留原文并标 `NEEDS_CONTEXT`，向文档解析／业务复核发出拆分请求。

可使用同一采购文件的资格章节、评分表、投标须知、合同条款、更正公告来澄清对象、阶段、后果和交叉引用。**不得**以模型常识补出未给的例外、供应商所在地或招标人意图。识别先针对可用文本；原件 OCR／表格结构不可靠时，不把未解析内容当作“没有限制”。

## 4 决策规则

### 4.1 三分类定义与优先顺序

| 标签 | 决定条件 | 业务含义和后续动作 |
|---|---|---|
| `MATCH` | 有原文支持地域属性或指定地区设实体义务**及**资格／实质响应／评分竞争作用；既包括评审时已有的机构，也包括投标时强制承诺中标后设置当地售后服务机构。 | 输出候选线索和证据，供业务／法律核查合理性、必要性与例外；不直接宣布违法。 |
| `NO_MATCH` | 文本及可用上下文足以确认该 Requirement 不构成本项，如仅约束服务结果且**不强制设本地实体**、只是地址事实、或明确属于其他项。 | 仅表示此要求**不命中 C1-01**；不表示整个项目已检查或合规。 |
| `NEEDS_CONTEXT` | 地域表述可能产生本项限制，但决定标签的对象、时间、竞争后果、引用条款或文本完整性缺失；或者可见材料显示特殊依据／例外争议，当前任务无法核定。 | 必须指出缺什么、去哪里补、由谁复核；不得为了凑覆盖而强判。 |

先拆要求，再看主体地域属性、作用阶段和竞争后果。完整文本足以排除时用 `NO_MATCH`；能确定主体地域身份成为门槛／评分因素时用 `MATCH`；**有实质歧义且补充信息可能使结论改变**时用 `NEEDS_CONTEXT`。不允许仅因“尚未完成完整法律论证”把所有明确门槛标为 `NEEDS_CONTEXT`。也不允许把所有出现“本地化服务”的语句机械标为 `NO_MATCH`：如果该词可能指既有本地实体，须索取定义。

### 4.2 四个判定问题

1. **谁被约束**：供应商／投标人，还是中标后的项目团队、服务资源、采购人地址？
2. **约束什么**：现有企业注册／营业／办公地域身份、距采购人的地点距离、现成分支机构、投标时必须承诺的指定地区实体机构，还是不限定机构形态的履约能力？
3. **何时生效**：投标／资格／评分时已具备，还是在投标时必须承担中标后设机构的义务？“承诺中标后设机构”不等于“已经有分支机构”，二者不能共用 `PREEXISTING_LOCAL_BRANCH`。
4. **带来什么后果**：不具资格、无效投标、扣分／加分、排序优先，还是单纯履约交付标准？

`MATCH` 的最低事实组合是**地域身份代理条件或强制设本地实体承诺 + 竞争后果**。没有竞争后果的地理描述不命中；若后果可能藏在引用条款里而未见引用，转 `NEEDS_CONTEXT`。评分表的本地注册加分也命中，即使外地供应商尚可投标，因为评分优势本身会影响竞争。仅要求达到到场／维修时效、允许自由组织服务的句子不因出现“本市”而命中。

### 4.3 subtype 与阶段

| 字段值 | 中文业务语义 | 边界 |
|---|---|---|
| `SUPPLIER_REGISTRATION_LOCATION` | 供应商注册／登记地、住所等企业主体所在地直接成为门槛或评分条件。 | 仅披露地址、项目交付地不算。 |
| `DISTANCE_TO_PURCHASER` | 将供应商既有办公／经营地点距采购人距离或同类地域半径用作门槛或评分。 | 对实际抵达／响应时限的要求，不能等同于企业地址距离。 |
| `PREEXISTING_LOCAL_BRANCH` | 投标／评审时在指定地区**已设有**分公司或其他分支机构。 | 中标后设机构的强制承诺不归入本子型，符合冻结条件时改用 `OTHER_RELATED`；单纯服务安排不命中。 |
| `OTHER_RELATED` | 本版仅批准一个明确情形：**投标时必须承诺中标后在指定地区设立售后服务机构**，且不承诺即无效或失分；包含“已有该机构或承诺中标后设置”两个可选路径的同一实质要求。 | 不把结果型服务承诺、可自选的临时人员安排或普通“本地化服务能力”装入此型；其他新情形须改版裁决。 |
| `NONE` | 非 `MATCH` 的占位子型。 | `NO_MATCH` 和 `NEEDS_CONTEXT` 均须 `NONE`，待补全后可重标。 |

`business_stage` 枚举遵循蓝图：`QUALIFICATION`（资格准入及不满足即无效的实质响应）、`SCORING`（评审因素）、`TECHNICAL`（技术／服务要求）、`CONTRACT`（合同履约）。投标时必须作出中标后设当地实体承诺且不承诺即投标无效，按 `QUALIFICATION`，不是按机构实际设立时间标 `CONTRACT`。若同一要求既是资格条件又在评分中加分，拆成两条分别标阶段并通过共同来源关联；在无法拆分时保留主竞争作用，并记录第二作用于上下文和复核备注。阶段未知时输入可为 `null`，并须明确缺失原因。

### 4.4 证据与弃权门槛

- `MATCH`：引述**最短可核对原文**，覆盖地域条件及其资格／评分后果；若后果在另一条款或评分表，证据列表应分别给出原文及定位，不能拼造一段“合成引文”。
- `NO_MATCH`：若含易误报词，保留证明其是履约承诺／事实描述的原文，供 hard negative 复核；常规负例可无命中证据，但保留 source locator。
- `NEEDS_CONTEXT`：引述歧义原文，列出缺失问题，如“该服务能力是否要求投标时已有本市实体？”；若原文本身不可读，证据可为 `null`，但 `parser_quality`、定位及缺失原因不得为空。
- 证据须能回到 `project_id + document_id + document_version + page/section/offset` 或等效定位；`evidence_text` 必须为原文连续片段，不能是推断或法条摘要。
- `confidence` 是模型对当前分类的内部置信信息，不是违法概率，也不能单独改变标签；歧义关键事实缺失时应弃权并触发人工／数据复核。

## 5 接口契约 V0.1

**输入粒度**：一条 Requirement，携带最小必要上下文。业务组定义语义，数据组实现正式 JSON Schema，算法组按已冻结 schema 生成输出；下面的 JSON 为可测契约实例，不预先代替数据组的最终 schema 文件。

```json
{
  "task_id": "C1-01_LOCAL_ENTRY_PRECONDITION",
  "requirement_id": "REQ-001",
  "project_id": "P-001",
  "document_id": "DOC-001",
  "document_version": "V1",
  "clause_text": "投标人须为本市注册企业。",
  "business_stage": "QUALIFICATION",
  "context": null,
  "source_location": {"page": 8, "section": "供应商资格条件"},
  "parser_quality": "PASS"
}
```

输入字段说明：`clause_text` 是该原子要求及足以读懂它的原句；`context` 只放相邻条文、评分表或引用条款的**可追溯原文**，没有时为 `null`；`business_stage` 由章节或条件功能决定，不靠“技术／商务”标题猜测；`parser_quality` 至少表达 `PASS`／`UNCERTAIN`，后者不能被静默视为正常文本。

```json
{
  "item_id": "C1-01_LOCAL_ENTRY_PRECONDITION",
  "requirement_id": "REQ-001",
  "match_state": "MATCH",
  "subtype": "SUPPLIER_REGISTRATION_LOCATION",
  "evidence_text": "投标人须为本市注册企业。",
  "evidence_spans": [{"text": "投标人须为本市注册企业。", "document_id": "DOC-001", "document_version": "V1", "page": 8, "section": "供应商资格条件"}],
  "evidence_refs": [{"document_id": "DOC-001", "document_version": "V1", "page": 8, "section": "供应商资格条件"}],
  "reasoning_factors": ["supplier_location_attribute", "pre_award_condition", "market_entry_gate"],
  "missing_context_questions": [],
  "confidence": 0.96,
  "human_review_required": false
}
```

输出字段不变量：`item_id` 固定；`match_state` 只能取三值；`MATCH` 必须有非 `NONE` 子型、证据及非空 `evidence_refs`；其余两类必须为 `NONE`；`NEEDS_CONTEXT` 必须有非空 `missing_context_questions`、`human_review_required=true`；`NO_MATCH` 的空证据使用 `null` 而不是伪造引文。`evidence_text` 是主要原文片段；跨条款条件及后果须以 `evidence_spans` 分别列出每段原文及定位，`evidence_refs` 为这些片段对应的定位列表，不许将几段原文拼成一段；未取得任何可读原文时 `evidence_spans=[]`。`human_review_required=false` 只表示该**模型分类**没有因缺上下文自动入队，不表示免除后续业务／法律复核。`reasoning_factors` 是可检查的事实标签，不输出私有思维链；新增取值必须由业务和数据组共同版本化。

## 6 边界样例与反事实测试

以下都是**为定义规则而写的合成样例**，不是具体项目的行政认定。一个样例只说明本任务标签。

| 编号 | 原子要求 | 标签／子型 | 必须说明的理由 |
|---|---|---|---|
| P1 | “投标人须在本市注册，否则投标无效。” | `MATCH` / `SUPPLIER_REGISTRATION_LOCATION` | 既有注册地是准入条件。 |
| P2 | “供应商办公地点距采购人不超过20公里得5分。” | `MATCH` / `DISTANCE_TO_PURCHASER` | 既有地点距离直接影响评分。 |
| P3 | “投标人须在本行政区域内已设立分公司。” | `MATCH` / `PREEXISTING_LOCAL_BRANCH` | 投标时已具备地区分支机构。 |
| P4 | “投标人具有本地分支机构的，技术评分另加3分。” | `MATCH` / `PREEXISTING_LOCAL_BRANCH` | 虽可参与，既有机构仍获竞争性加分。 |
| N1 | “中标供应商在合同签订后建立两小时响应服务机制。” | `NO_MATCH` / `NONE` | 要求结果能力，未指定既有地域实体。 |
| N2 | “本项目服务地点为采购人位于本市的办公楼。” | `NO_MATCH` / `NONE` | 地点事实，没有供应商门槛。 |
| N3 | “中标后在项目现场配备驻场人员。” | `NO_MATCH` / `NONE` | 履约安排，没有投标时主体身份条件。 |
| U1 | “供应商应具备本地化服务能力。” | `NEEDS_CONTEXT` / `NONE` | “本地化”是否意味着既有主体机构及是否评分不明。 |
| U2 | “按照资格条件第七项提供本市服务证明。”但第七项未提供。 | `NEEDS_CONTEXT` / `NONE` | 引用内容决定条件性质；需补第七项。 |
| U3 | OCR 为“距采购人不超过[无法辨认]，得分见附表”，附表缺失。 | 暂定 `NEEDS_CONTEXT` / `NONE`，正式标签为空 | 属 `REWORK_SOURCE`，先补原件与附表；不进入普通缺上下文训练／盲测切片。 |
| O1 | “投标人注册资本不少于5000万元。” | `NO_MATCH` / `NONE` | 可能是别项问题，但不属于本项地域属性。 |

**反事实对 A**：`投标人须在本市已设分公司` → `MATCH`；只改关键事实为 `中标后须建立满足两小时响应要求的服务机制` → `NO_MATCH`。  
**反事实对 B**：`供应商在采购人20公里内设有办公点的得5分` → `MATCH`；只改评分依据为 `承诺两小时内到达项目现场的得5分` → `NO_MATCH`。  
**反事实对 C**：`本市注册的供应商得3分` → `MATCH`；只改为 `供应商须提交营业执照并载明注册地址` → `NO_MATCH`。

上述对偶的 `pair_id`、相同 `leakage_group_id` 和最小文本差异说明应随标注记录；只有改变关键事实后标签正确翻转，才证明模型学到边界而非地名关键词。

## 7 从案例到数据的交付关系

业务组交付 `C1_01_Label_Guide_V0.1.md`、`C1_01_Case_Intake_V0.1.jsonl` 与 `C1_01_InternalSilver_CasePack_V0.1.jsonl`；本说明固定其语义，Label Guide 再细化标注操作、争议裁决和示例。案例必须记录来源项目、原文版本、定位、原子要求、主标签、子型、阶段、证据、复核状态及 `label_authority=INTERNAL_SILVER`。收集人猜测的子型不得直接变成正式标签。

数据组接收**已核验且可追溯**的案例，完成去重、近重复、`leakage_group_id`、按项目／模板家族拆分及 Schema 验证。`CollectedCase != TrainingCase`，且 `DataClean != LeakageSafe`：清洁文本也可能因同项目或同模板泄漏盲测。推荐案例池覆盖典型正例、隐蔽正例、普通负例、高相似负例、缺上下文及反事实对；蓝图建议约 200 条内部接受样本、至少 30 个项目／模板家族，并非本任务文档单独设立的强制生产指标。

算法组使用已冻结接口完成 baseline 和候选模型，不自行改标签语义，不读取 `blind_test_gold.jsonl`。测试组独立持有盲测真值，至少覆盖 MATCH 召回、精度、hard negative 误报率、证据命中、反事实一致性、结构化输出有效率及 NEEDS_CONTEXT 能力。蓝图中的 Demo Gate 由项目负责人和测试负责人在盲测真值未打开之前冻结；`PASS_DEMO` 不等于生产就绪。
