第 37 页

但 PDF 内部：

三、PDF 本质上是什么？

初学时非常容易把 PDF 想成：

一个“只读版 Word”。

其实这不准确。

PDF 更接近：

一套告诉渲染器“页面上的东西应该画在哪里”的固定版式描述。

它首先关心的是：

这里画一个字
那里画一条线
这里放一张图
那里放一个文本块

而不是：

这是一级标题
这是第二段
这是表格第三行第二列
这是资格条件

四、这就是 PDF 和 DOCX 的根本区别之一

DOCX 更偏：

文档结构。

PDF 更偏：

页面最终长什么样。

可以先这么理解：

DOCX
更像“文章的结构说明”

PDF
更像“最终打印出来的页面”

五、所以 PDF 最擅长什么？

保持：

  • 字体；
  • 页面；
  • 位置；
  • 打印效果；
  • 跨设备视觉一致性。

也正因为这样：

它并不天然适合机器恢复语义结构。

六、第一个核心心智模型

VisualLayout≠SemanticStructure \boxed{ VisualLayout \neq SemanticStructure }

人眼看到：

“这是标题。”

PDF 可能只知道：

“这一行字号 18、粗体、坐标在页面顶部。”

七、先把 PDF 分成三类

政府采购文件里，我们至少会碰到：

① 文字型PDF

② 扫描型PDF

③ 混合型PDF

这三种必须分清。

八、第一类：文字型 PDF

比如：

Word 导出 PDF。

页面看起来是文字。

内部通常也存在：

Text Layer。

你可以：

  • 鼠标选择文字；
  • 搜索关键字；
  • 复制粘贴。

这种 PDF：

通常优先做原生文字提取。

九、第二类：扫描型 PDF

来源可能是：

纸质文件
↓
扫描仪
↓
PDF

这时候整页对机器来说可能只是：

Image

也就是：

一张照片。

十、你人眼看到的是

供应商应……

但 PDF 内部可能只有：

一张 2480 × 3508 像素图片

没有字符：

应
商

这个概念。

十一、这时普通 extract_text() 会怎样？

可能：

返回空字符串

或者：

几乎没有文字

十二、这种情况才真正需要 OCR

OCR：

Optical Character Recognition

光学字符识别。

它做的是：

Pixel
↓
识别字形
↓
Character
↓
Text

十三、第三类：混合型 PDF

这其实很常见。

例如：

第1～20页
正常电子文本

第21页
扫描盖章文件

第22～40页
正常文本

附件
又是扫描件

所以：

不能只给整个 PDF 打一个“可提取/不可提取”的标签。

更合理的是：

Page-level Detection

按页判断。

Page 2   Native Text
Page 3   Native Text

十五、为什么我特别强调“不要所有 PDF 都 OCR”？

因为很多人会觉得：

“OCR 什么都能认，那我把所有页面先转图片再 OCR，不就统一了吗？”

听起来很省事。

实际通常不是最佳方案。

十六、如果 PDF 本来就有高质量文字层

原生提取可以直接拿到：

政府采购法

OCR 却需要：

图片
↓
识别
↓
猜这是哪几个字

无端增加了一次：

识别错误机会。

十七、尤其政府采购文件里有很多敏感字符

比如：

500万元

OCR 如果变成：

S00万元

问题就非常大。

十八、再比如

原文：

≤3%

OCR：

< 8%

对于普通文章：

也许只是一个错字。

对于：

可能直接改变业务含义。

十九、再比如型号

可能被识别成：

二十、再比如法律条款

第三十一条

变成：

RAG 检索：

可能就被影响。

二十一、所以 OCR 最重要的心智模型是

OCR=必要时把像素恢复成文字 \boxed{ OCR = 必要时把像素恢复成文字 }

而不是：

OCR=所有文档解析第一步 \boxed{ OCR = 所有文档解析第一步 }

   ▼

即使：

成功，

为什么？

因为第二个大问题来了：

二十四、阅读顺序是什么？

人类看文件时会自动知道：

先读标题
再读正文
从左到右
从上到下

但复杂 PDF：

阅读顺序可能被打乱。

人眼看到：

为什么？

因为它可能按：

而不是：

二十七、于是文字都“提取成功”了

一个字都没丢。

但语义：

已经乱了。

这就是：

CharacterCorrect≠DocumentCorrect \boxed{ CharacterCorrect \neq DocumentCorrect }

二十八、这对采购数据有多危险？

原本：

解析后变成：

然后资格要求：

二十九、以后条款切分会怎样？

模型会把：

误认为：

所以解析错误：

会一路传到训练数据。

三十、这就是数据工程中的一个重要概念

上游一个小错误：

会向下游传播成：

↓

三十一、所以 Parsing 绝对不是“辅助小工具”

它决定：

你后面数据集到底是不是在描述真实文档。

三十二、第三个大问题：页眉页脚

采购文件经常每页都有：

第 37 页 / 共 128 页

这些视觉上：

很自然。

人类几乎自动忽略。

提取 128 页以后：

项目编号：XXXX
项目编号：XXXX
……

可能出现：

三十四、这会产生什么问题？

首先：

三十五、其次 Token 浪费

模型每次读长文档：

都反复读无用页眉页脚。

三十六、再次，切分污染

原本：

跨页。

中间突然变成：

第37页
某某采购中心
项目编号XXX

后续切条款：

会被干扰。

三十七、还有一个更隐蔽的问题

模型可能把：

错误拼进：

正文句子。

三十八、所以“去页眉页脚”不是简单删除第一页和最后一页

而是：

识别页面中重复出现、位置稳定、语义上属于版式装饰的区域。

三十九、一个好的方法通常会利用

重复文本
+

例如：

连续80页出现相同字符串

很可能：

Header。

+

+

可能：

Footer。

四十一、但是不能机械删除“页面顶部所有文字”

因为第一页顶部可能就是：

甚至：

四十二、所以这里再次体现

Rules + Context

不能只：

写死坐标。

四十三、第四个大问题：换行

PDF 经常是按视觉行存储。

四十五、如果我们直接把每行当句子

就会出现：

二百四十三、本阶段 6 个核心心智模型总结

核心心智模型 真正含义
① 看得见 ≠ 有文字层 扫描 PDF 可能只是图像
② Extract ≠ Parse 拿到字符不代表阅读顺序和结构正确
③ Parsing = 内容 + 结构 + 来源位置 不能只保存大字符串
④ OCR 是后备方案 有可信原生文字时优先原生提取
⑤ 早期不要丢 Provenance 页码、bbox、来源、Parser 版本以后都很有价值
⑥ Parsing Quality 由业务决定 对评分表、金额、法规引用等要更严格
