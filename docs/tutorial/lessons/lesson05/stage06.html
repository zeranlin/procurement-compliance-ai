上一阶段我们最后停在：

W′=W+ΔW W' = W + \Delta W

这句话其实已经把 LoRA 的门打开了一半。

Base Model 原来的参数是：

W W

领域微调真正需要学习的是：

ΔW \Delta W

也就是：

为了让模型更符合政府采购任务，原来的权重到底需要发生怎样的变化？

Full Fine-Tuning 的思路是：

直接让整个 WW 自己变化。

LoRA 的思路完全不同：

冻结 WW，不直接训练它；另外学习一个很小的 ΔW\Delta W。

而 LoRA 最核心的一步是：

ΔW=BA \boxed{ \Delta W = BA }

本阶段只需要彻底搞懂这一件事。

最终形成：

LoRAUpdateModel_V0.1

一、本阶段只有一个核心问题

假设 Transformer 中有一个巨大线性层：

y=Wx y = Wx

其中 WW 有几百万甚至几千万参数。

如果我们想微调它，为什么不直接训练整个：

W W

而要额外增加：

A A

和：

B B

两个小矩阵？

整个 LoRA 流程可以先压缩成：

输入 x
  │
  ├──────────────► Frozen W ──────────┐
  │                                   │
  └──► A ──► 小空间 ──► B ───────────┤
                                      ▼
                                    相加
                                      │
                                      ▼
                                 最终输出 y

数学上就是：

y=Wx+BAx \boxed{ y = Wx + BAx }

先把这张图锁进脑子。

二、先锁死 5 个核心心智模型

心智模型 1：LoRA 不替换 Base Model，而是在原模型旁边学习一个“修正量”

原模型：

Wx Wx

LoRA：

BAx BAx

最终：

Wx+BAx Wx + BAx

所以 LoRA 不是：

把 Base Model 某一层删掉，再装一个小层。

而是：

Base Model 保留原能力，LoRA 在旁边提供任务相关的修正。

因此：

LoRA=BaseBehavior+TaskSpecificCorrection \boxed{ LoRA = BaseBehavior + TaskSpecificCorrection }

心智模型 2：真正学习的是 ΔW\Delta W，不是重新学习 WW

LoRA 可以理解成：

W′=W+ΔW W' = W + \Delta W

其中：

W W

冻结。

而：

ΔW \Delta W

可学习。

于是训练问题从：

“重新学习这个巨大矩阵。”

变成：

“学习这个巨大矩阵需要改变多少。”

这是一种非常重要的思维转变。

心智模型 3：LoRA 的关键假设是——有用的参数变化可能存在于低维子空间

LoRA 并不是说：

原矩阵 WW 本身是低秩的。

这一点千万别混。

它真正假设的是：

下游任务所需要的权重变化 ΔW\Delta W，可能不需要拥有完整矩阵那么高的自由度。

因此：

W可以很复杂 \boxed{ W\ 可以很复杂 }

但：

ΔW可能可以用低秩结构近似 \boxed{ \Delta W\ 可能可以用低秩结构近似 }

这是 LoRA 最核心的数学直觉。

心智模型 4：Rank 控制的是“允许 LoRA 学多少种独立变化方向”

如果：

ΔW=BA \Delta W = BA

中间维度是：

r r

这个 rr 就叫：

Rank

秩 / 低秩维度

直觉上：

rr 越小，允许表达的变化空间越受限制。

rr 越大，LoRA 拥有更多调整自由度。

今天先理解这个意义。

具体：

r 到底选 8、16、32 还是 64？
alpha 怎么配？
dropout 怎么配？

放到下一阶段专门解决。

心智模型 5：LoRA 省参数的真正原因，是把一个“大矩阵”拆成两个“瘦矩阵”

这是最重要的计算直觉。

一个大矩阵：

ΔW \Delta W

本来可能需要：

dout×din d_{out}\times d_{in}

个参数。

LoRA 改成：

BA B A

只需要：

r(din+dout) r(d_{in}+d_{out})

个参数。

只要：

r≪din,dout r \ll d_{in},d_{out}

参数量就会大幅下降。

五、LoRA 怎么做？

LoRA 不直接训练：

W W

而是：

W′=W+BA W' = W + BA

其中：

A∈ℝr×din A\in\mathbb{R}^{r\times d_{in}}

而：

B∈ℝdout×r B\in\mathbb{R}^{d_{out}\times r}

所以：

      A

      │

      │
      ▼
      B
r → d_out
      │
      ▼

六、这里真正发生了一次“压缩 → 展开”

矩阵 A：

A:din→r A: d_{in}\rightarrow r

把高维输入：

投影到一个很小的低维空间。

然后矩阵 B：

B:r→dout B: r\rightarrow d_{out}

再把这个低维变化：

投影回原来的输出维度。

所以 LoRA 的直觉可以压成：

A
   ↓

   ↓

这个“低维任务变化空间”：

就是 LoRA 真正省参数的地方。

八、但最终 ΔW\Delta W 的形状没有变

这一点特别重要。

虽然：

很小，

也就是说：

九、这就是 LoRA 最漂亮的地方

它不是：

只修改原矩阵的一小块。

也不是：

输出一个低维答案。

最终产生的修正：

仍然作用在：

只是这个变化：

十、为什么叫 Low-Rank Adaptation？

Low-Rank Adaptation

低秩适配

名字来自：

ΔW=BA \Delta W = BA

因为它的秩最多受：

r r

限制。

可以写成：

rank(BA)≤r \operatorname{rank}(BA)\le r

所以当：

r≪4096 r\ll4096

时：

ΔW\Delta W 是一个低秩变化。

这就是：

LoRA

名字真正的来源。

十一、低秩到底意味着什么？

不要把“秩”搞成纯数学名词。

可以把一个大矩阵能够做的变化想成：

有很多很多可能的独立方向。

完整矩阵更新：

方向1
方向2
方向3
方向4
……
可能非常多

LoRA 说：

对这个具体领域任务，也许实际上只需要少数几个主要变化方向。

例如非常粗略地想象政府采购任务：

变化方向 A
更关注资格条件

变化方向 B
减少关键词Shortcut

变化方向 C
证据不足时更愿意needs_review

变化方向 D
输出结构更加稳定

真实神经网络当然不会这么整齐地“一方向对应一规则”。

但这种类比能帮助理解：

领域适配可能只需要改变原模型行为空间中的有限几个主方向。

因为 Base Model 已经不是一张白纸。

所以可能不需要：

这么多独立变化自由度。

只需要：

心智模型只记：

二十六、现在来算 LoRA 参数量公式

W∈ℝdout×din W \in \mathbb{R}^{d_{out}\times d_{in}}

二十七、什么时候 LoRA 不再“很省”？

如果：

越来越接近：

那么：

自然越来越大。

所以 LoRA 有意义的基本前提之一就是：

r≪d \boxed{ r\ll d }

即：

中间低秩空间远小于原模型隐藏维度。

三十九、把整个阶段压成最精准的 5 句话

第一，LoRA 不重新训练 Base Weight，而是在冻结的 WW 旁边学习一个任务修正量 ΔW\Delta W。

第二，LoRA 的核心是 ΔW=BA\Delta W=BA：用两个瘦矩阵表示一个完整高维权重变化。

第三，低秩假设针对的是“任务所需的权重变化可能只占少数有效方向”，不是说 Base Model 本身很简单。

第四，Forward 仍然使用完整 Base Model，最终输出是 Wx+BAxWx+BAx；Backward 主要更新 A、B，而 W 保持冻结。

第五，LoRA 节省参数的本质来自 r(din+dout)≪dindoutr(d_{in}+d_{out})\ll d_{in}d_{out}，但 Rank 多大、装在哪些模块上，必须由任务和 Benchmark 决定。
