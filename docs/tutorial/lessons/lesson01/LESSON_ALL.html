1. 第一课总问题：机器学习到底在“学习”什么？

机器学习不是把文件“塞进模型”，而是从有限历史样本中寻找一个能推广到未知样本的映射规律。第一阶段先建立所有后续课程共同使用的最小语言。

公式 / 关键表达

机器学习 = 从有限历史样本中，寻找一个可以泛化到未知样本的映射规律

2. 从 X → Y 开始

任何监督学习任务都应该先写清楚输入 X 和目标 Y。模型只是连接 X 与 Y 的参数化函数。

公式 / 关键表达

X → fθ(X) → Ŷ

3. 政府采购任务如何定义 X

如果任务是审查供应商资格条件，最简单的 X 可以是一条资格文本；更成熟的 X 还可以加入采购标的、项目类型、地区、时间和上下文。

政府采购案例 / 例子

“供应商注册资本不得低于5000万元”可以作为最小 X；如果缺少项目背景，模型能力上限也会被限制。

4. Y 是什么：标签就是老师

Y 是训练时告诉模型“什么叫正确”的目标。二分类中可以先用 1 表示存在潜在风险、0 表示未发现明显风险。

专家心智模型

标签设计决定模型被教成什么样。错误标签会把梯度推向错误方向。

5. Ŷ 是模型的预测

模型不会直接看到“真理”，它先根据当前参数生成预测 Ŷ，再与 Y 比较。训练早期 Ŷ 往往很差，这本来就是正常状态。

6. 模型 fθ 是什么

fθ 表示一个由参数 θ 控制的映射。逻辑回归、神经网络、Transformer 都只是更复杂的 fθ。

公式 / 关键表达

Ŷ = fθ(X)

7. 参数 θ 到底是什么

参数是训练真正修改的对象。在线性模型中是权重和偏置；在大模型中则是大量矩阵中的数值。

政府采购案例 / 例子

一个三特征模型可以写成 θ=[w1,w2,w3,b]。

8. 一个最小的政府采购特征模型

为了建立直觉，可以先把条款表示成几个简单特征：是否限制注册资本、是否要求本地分支、是否限制成立年限。

公式 / 关键表达

X=[x1,x2,x3]

9. 线性打分

最简单模型把各特征乘以权重再相加，得到一个原始分数 z。

公式 / 关键表达

z=w1x1+w2x2+w3x3+b

10. 权重意味着什么

如果 w2 很大且为正，说明“本地分支要求”在当前数据里会把模型预测推向风险一侧。但注意：高权重只表示模型依赖它，不等于法律上天然违规。

11. Loss：模型怎样知道自己错了

Loss 把预测与真实标签之间的差异压缩成一个可优化的数值。训练的直接目标不是“理解政府采购”，而是降低我们定义的 Loss。

公式 / 关键表达

Loss = L(Ŷ,Y)

12. 为什么 Loss 必须可优化

如果一个评价标准不能对参数变化提供连续反馈，训练就很难知道下一步朝哪个方向改。后面我们会用交叉熵建立这种可微反馈。

13. 训练就是反复纠错

每一批样本都给模型一个反馈：哪些预测错、错多大、哪些参数应该往什么方向动。大量微小更新叠加后形成能力。

公式 / 关键表达

θ(t+1)=θ(t)-η∇θL

14. Gradient 是什么

梯度告诉我们：如果稍微改变某个参数，Loss 会朝什么方向变化、变化多快。第一阶段先记住它是“纠错方向”。

15. Learning Rate η 是步长

梯度给方向，学习率决定一次改多少。太大可能越过好解甚至发散，太小则几乎学不动。

16. 数据 = 模型的经验

模型没有亲自参与采购活动，它的“经验世界”来自训练样本。数据中没有覆盖的模式，模型就缺少直接经验。

专家心智模型

心智模型①：数据就是经验。

17. 信息决定能力上限

如果 X 中没有项目背景、时间、地区或适用规则，模型不可能稳定利用这些缺失信息。

专家心智模型

心智模型②：信息决定上限。

18. 标签 = 老师

同样的 X，如果专家标注标准混乱，模型会接收到相互冲突的学习信号。

专家心智模型

心智模型③：标签就是老师。

19. 学习 = 减少 Loss

模型并不知道我们心里的业务目标，它只接触到被编码进 Loss、数据和训练流程里的目标。

专家心智模型

心智模型④：模型只会优化被明确写进训练系统的东西。

20. 能力 = 泛化

训练集做得好只能说明模型适应了历史样本；真正能力要看未见项目、未见年份、未见地区和边界案例。

专家心智模型

心智模型⑤：泛化比记忆更重要。

21. 为什么 99% 训练准确率可能毫无意义

如果模型只背住模板、机构名称、固定句式，它可以把训练集做得极好，却在新项目上失败。

22. Shortcut Learning：模型会走捷径

模型倾向利用最容易降低 Loss 的特征，而不是我们希望它掌握的业务原则。

政府采购案例 / 例子

若训练集中带数字的条款大多被标风险，模型可能学成“出现数字→风险”。

23. 数字捷径的反例

“7×24小时故障响应服务”包含数字，但不因此自动构成不合理限制。这个反例能帮助模型打掉“数字=风险”的错误捷径。

24. 相关性不等于规则

模型学到的是统计相关。它不能凭一个关键词自动推出法律结论，尤其政府采购判断需要上下文、必要性、比例性和适用规则。

25. 从关键词升级到抽象原则

真正希望模型学习的是“条件是否与履约需要合理相关、是否造成不必要竞争限制”等更稳定原则，而不是死记“本地”“5000万”等词。

26. 一个样本如何推动参数更新

样本进入模型得到预测，预测与标签计算 Loss，反向传播得到梯度，优化器更新参数。

公式 / 关键表达

X → Ŷ → Loss → Gradient → Update θ

27. 为什么需要很多样本

单个案例只能提供局部反馈；大量多样样本让参数在不同方向的反馈中逐渐形成更稳健的表示。

28. 为什么高质量反例很值钱

一个模型特别容易误判的反例，比十个重复的简单样本更能修正决策边界。

29. 政府采购二分类只是起点

最终 Y 可以扩展成风险类型、严重程度、依据、理由、修改建议和不确定性；但第一阶段先用简单任务理解学习机制。

30. 训练不等于知识复制

把法规 PDF 放进训练目录，并不意味着模型把条文一字不漏“存进去”。训练更像用样本不断改变参数，使其对某类输入形成概率性响应。

31. 模型权重不是数据库

权重可以压缩统计规律，但不适合承担频繁变化、需要精确引用的法规事实，因此后续会引入 RAG。

32. 第一阶段完整链路

把所有概念串成一条链：输入、模型、预测、误差、梯度、参数更新、泛化评测。

公式 / 关键表达

X → Model → Ŷ → Loss → ∇ → θ更新 → 新样本泛化

33. 思维实验：模型到底利用了什么

假设模型对所有含“本地”的条款都判风险，你应该构造“项目实施地点在本地但不限制供应商注册地”的反例测试它。

34. 阶段掌握标准

你应能解释 X、Y、Ŷ、Loss、θ、Gradient、Learning Rate 和 Generalization，并能说明“训练模型”为什么不是“把知识复制进去”。

  • 能写出一个政府采购任务的 X/Y
  • 能解释参数是训练真正修改的对象
  • 能说明 Loss 与业务目标的关系
  • 能举出一个 Shortcut Learning 反例
  • 能区分训练成绩与泛化能力

35. 用一个完整二分类例子把 X、Y、预测串起来

假设第一版任务是：判断一条供应商资格条件是否存在潜在不合理限制风险。为了教学，先把输出压缩成二分类：

Y={1,存在潜在风险0,未发现明显风险 Y=\begin{cases} 1,&\text{存在潜在风险}\\ 0,&\text{未发现明显风险} \end{cases}

例如，“供应商须在项目所在地设有分公司”可以作为潜在风险样本；“供应商应依法缴纳社会保障资金”可以作为无明显风险样本。这里的例子用于机器学习结构教学，并不意味着现实中仅凭一句话就能自动形成最终法律结论。实际判断仍要结合采购标的、履约必要性、市场竞争状况、有效法规和项目上下文。

模型真正接收的是 X，产生预测 Ŷ\hat Y，训练系统再拿 Ŷ\hat Y 与 Y 比较。如果 X 缺信息，即使标签再准确，模型也可能学不到你希望它掌握的条件性判断。

36. 把自然语言先简化成三个可观察特征

为了理解“参数到底在学什么”，先暂时不考虑 Transformer，把一句采购条款手工表示为三个特征：

X=[x1,x2,x3] X=[x_1,x_2,x_3]

其中：x1x_1 表示是否设置注册资本门槛，x2x_2 表示是否要求本地分支机构，x3x_3 表示是否设置成立年限限制。最简单模型可以写成：

z=w1x1+w2x2+w3x3+b z=w_1x_1+w_2x_2+w_3x_3+b

训练改变的是 w1,w2,w3,bw_1,w_2,w_3,b，而不是原始 PDF，也不是标签本身。大模型只是把“特征”从三个手工变量升级成了海量内部表示，把参数从几个数字升级成数十亿个矩阵元素，但基本思想仍然一致。

37. 一次训练更新到底发生了什么

假设某条真实风险样本被模型预测成低风险。训练系统先计算 Loss，再计算 Loss 对参数的梯度：

θt+1=θt−η∇θL \theta_{t+1}=\theta_t-\eta\nabla_\theta L

这句话可以翻成白话：先看错了多少，再判断每个参数该往哪个方向挪一点，然后挪一点。 训练一次不会让模型突然“懂政府采购”，能力来自成千上万次这样的微小纠错累积。

这也是为什么数据质量如此重要：错误标签会产生错误梯度；缺少上下文会让模型在错误信息基础上寻找捷径；高度重复的数据会让某些模式被反复强化。

38. “模型学知识”不是把法规原句存进某个参数

神经网络里的知识通常是分布式表示。你很难找到一个单独参数说“这个参数就是政府采购法第某条”。训练更像是在大量样本反馈下逐渐调整一个巨大函数的形状，使特定输入更容易映射到特定输出。

因此，把十万份法规 PDF 直接扔进训练流程，并不自动等于得到十万份法规的可靠可检索知识。对于需要精确、最新、可引用的法规内容，后续我们会更偏向 RAG；对于“如何审查、如何组织理由、如何识别典型风险模式”，SFT 和领域训练更适合塑造行为。

39. 为什么“信息决定上限”是第一课最值得记住的原则之一

如果只给模型一句“供应商须有五个同类业绩”，模型并不知道项目预算、采购复杂度、市场供应商数量，也不知道设置该条件的必要性说明。此时不存在一种训练技巧能让模型稳定利用根本没有输入的信息。

因此更成熟的任务表示可能是：

X=[条款,采购标的,上下文,地区,时间,适用规则] X=[\text{条款},\text{采购标的},\text{上下文},\text{地区},\text{时间},\text{适用规则}]

这意味着任务设计与数据 Schema 不是训练前的行政工作，而是模型能力设计的一部分。

40. “标签就是老师”还意味着老师必须有统一教学标准

如果专家 A 把某类本地服务要求全部标成风险，专家 B 认为必须区分“本地注册”和“本地履约服务能力”，模型会同时收到冲突信号。此时扩大模型规模并不能修复教学标准冲突。

未来政府采购训练数据至少应该保存：标签、风险类型、理由、法律依据、专家置信度、是否存在分歧，以及必要时的复核结果。二分类只是第一版实验接口，不应被误认为现实世界只有 0 和 1 两种真理。

41. 泛化：为什么“背会历史文件”不算真正能力

假设模型训练集准确率达到 99%，但新项目测试只有 55%。这说明它可能记住了历史模板、代理机构风格、固定关键词甚至项目名称，却没有形成可迁移规律。

真正希望的能力是：换项目、换措辞、换地区、换年份以后，仍然能识别更稳定的业务逻辑。后面的过拟合、数据分布、OOD 和因果阶段，本质都在进一步回答“怎样知道模型是否真的形成了这种能力”。

42. Shortcut Learning：模型会主动寻找比专家原则更容易的捷径

如果风险样本里经常出现“5000万元”“10年以上”“本市”等词，而正常样本很少出现，模型可能把数字和地名当成非常好用的 shortcut。它不需要理解竞争限制，只要抓住词频就能降低 Loss。

所以必须准备反例。例如“7×24 小时故障响应服务”有数字，但数字本身不能推出风险；“项目履约地点位于本市”出现“本市”，但与“供应商必须在本市注册”并不是同一约束。这些反例会在第六阶段发展成 Hard Negative 与 Contrastive Data。

43. 第一阶段思维实验：到底应该改模型还是改 X

假设模型对某些复杂技术参数一直判断不稳定。你有两个选择：A）直接换更大的模型；B）把采购标的、参数用途、市场可替代产品数量等信息加入 X。应该先问：错误是不是由信息缺失导致？

如果专家在只看原始 X 的情况下也无法稳定判断，那么让模型在相同信息条件下输出确定答案，本身就是任务定义不合理。这个思维实验会贯穿整门课程。

45. 第一阶段的五个核心心智模型

  1. 数据 = 经验：模型世界来自训练样本，而不是模型名称。
  2. 信息决定上限：X 中不存在的信息，模型无法可靠利用。
  3. 标签 = 老师：错误、冲突、粗糙标签会直接塑造错误行为。
  4. 学习 = 减少 Loss：模型不会读懂我们的愿望，只会响应训练信号。
  5. 能力 = 泛化：真正能力体现在未知项目，不体现在训练集背诵成绩。

1. 第二阶段总问题：Loss 下降就代表模型变好了吗？

不一定。训练集越来越好，可能只是模型越来越擅长历史样本。第二阶段建立欠拟合、过拟合和泛化诊断框架。

2. Underfitting：连训练数据都没学好

Train 和 Validation 都差，说明模型没有捕捉到足够规律。

政府采购案例 / 例子

Train=61%，Val=59%：首先考虑输入信息、模型容量、数据/标签质量和优化问题。

3. 欠拟合不等于“再训久一点”

如果 X 缺信息、标签混乱或模型容量不足，多跑 Epoch 可能只是浪费算力。

专家心智模型

心智模型①：学不好 ≠ 训练不够。

4. 欠拟合原因 1：输入信息不足

只给单句资格条款，而判断必须依赖采购标的和上下文时，模型上限已经被 X 限制。

5. 欠拟合原因 2：标签噪声过大

专家标准不一致会让同类样本向相反方向拉参数，Train Loss 也可能难以下降。

6. 欠拟合原因 3：模型表达能力不足

过于简单的模型无法表示复杂非线性关系时，会产生高 Bias。

7. 欠拟合原因 4：优化失败

学习率不合适、梯度没有正确更新、可训练参数配置错误，都可能让模型看似“没学会”。

8. Overfitting：训练集近乎完美，验证集明显落后

Train=99.7%，Val=71% 是典型警报：模型记住了训练集特有模式。

9. 过拟合的本质

模型对特定训练样本过于敏感，没有学到足够稳定的规律。

10. 高 Bias 与高 Variance

Bias 可以理解为方法太简单导致系统性偏差；Variance 是模型对训练样本变化过于敏感。

公式 / 关键表达

Expected Error ≈ Bias² + Variance + Noise

11. 现代深度学习中的 Bias/Variance 只是心智模型

这个分解不是诊断大型 Transformer 的万能公式，但能帮助我们区分“根本没学会”和“只会训练集”。

12. Noise：不可避免的误差来源

现实世界和标签本身可能含噪声。政府采购边界问题甚至专家之间也可能合理分歧。

13. Train / Validation / Test 三分法

Train 用于学习参数；Validation 用于选择超参数、阈值和 checkpoint；Test 用于最终考试。

14. 为什么 Validation 不能当 Test

如果你反复看 Validation 并据此修改模型，它已经参与开发；最终还需要更独立的 Test。

15. 测试集污染：反复调到 Test 上

每次看 Test 错误就针对性修，久而久之 Test 也变成了训练的一部分。

16. Early Stopping

当 Train Loss 继续下降而 Val Loss 开始上升，应考虑停止训练并选择较早 checkpoint。

政府采购案例 / 例子

Epoch3 Val 最好，Epoch4/5 变差，就不要迷信最后一轮。

17. Shortcut Learning 再深入

模型可能利用机构名、模板、投诉决定措辞等无关特征获得高分。

18. 如何发现模型走捷径

问“模型到底利用什么信息做出了答案？”并通过遮挡、同义改写、最小对比样本测试。

19. Hard Example

决策边界附近的难例比大量显然样本更能暴露模型是否真的理解。

20. Hard Negative

看起来特别像风险，但实际上并非如此，用来压低误报。

21. Hard Positive

看起来很正常，但真正存在风险，用来减少漏报。

22. Contrastive Pair

相似措辞、不同标签，迫使模型学习真正差异。

23. 为什么同项目不能随机拆分

同一项目可能有招标文件、更正公告、中标结果、质疑答复和投诉处理决定。随机按文档拆分会泄漏项目身份和答案。

37. 第二阶段掌握标准

你应能看到 Train/Val 曲线后判断欠拟合或过拟合，并能设计 Project/Time/Slice 隔离的评测。

38. 一个典型欠拟合诊断例子

假设资格条件分类任务训练后得到：Train Accuracy = 61%，Validation Accuracy = 59%。二者都低，而且非常接近。这通常不像过拟合，更像模型根本没有学到足够规律。

但“继续训练更久”只是可能方案之一。还应检查：X 是否缺少上下文、标签是否混乱、模型容量是否太小、输入表示是否失真、学习率是否不合理、真正可训练的参数是否被正确打开。

39. 一个典型过拟合诊断例子

如果 Train Accuracy = 99.7%，Validation Accuracy = 71%，模型显然把训练数据拟合得非常好，却没有把能力带到未知样本。政府采购里最常见的原因之一，是模型学会项目模板、代理机构名称、文书固定格式或投诉决定里的答案提示。

训练成绩继续上涨并不值得庆祝。此时应该关注 Validation 曲线、测试隔离和错误样本，而不是盲目追加 Epoch。

40. Bias 与 Variance 的直觉

经典概念可以写成：

ExpectedError≈Bias2+Variance+Noise ExpectedError \approx Bias^2 + Variance + Noise

High Bias 可以理解为模型或表示方式太僵硬，连主要规律都学不好；High Variance 则意味着模型对某一批训练数据过于敏感。现代深度学习并不能总用这条式子机械诊断，但它仍然是理解“太简单”和“太贴训练集”之间张力的好框架。

41. Noise：并非所有错误都来自模型

在政府采购边界问题里，专家之间可能真实存在意见差异。此时测试标签本身可能有噪声。模型与标签不一致时，需要区分：模型错、专家标签错、还是问题本身具有不确定性。

因此未来 Y 可以比 0/1 更丰富：

Y={风险级别,专家意见,证据,依据,不确定性} Y=\{风险级别,专家意见,证据,依据,不确定性\}

42. Train / Validation / Test 三者不是三个同义的数据文件夹

Train 用来学习参数；Validation 用来选超参数、阈值、Checkpoint 和早停位置；Test 应尽量模拟一次真正的最终考试。如果你每天看 Test 再改模型，Test 就逐渐变成了 Validation。

这也是为什么成熟系统会进一步设置 Hidden Challenge Set：开发团队平时看不到答案，只在重大版本评估时使用。

43. 项目级切分：政府采购数据最容易忽略的泄漏

一个项目可能同时存在采购公告、招标文件、更正公告、中标公告、质疑答复和投诉处理决定。如果随机按“文档”切分，同一项目很可能一部分进入 Train、一部分进入 Test。

模型此时可能通过项目名称、标的、机构、特殊术语甚至后续处理结果间接“认出答案”。所以更合理的最小隔离单元通常是 Procurement Project，而不是 Document。

44. 时间切分：部署世界通常是 Past → Future

随机切分假设训练和测试来自近似同一分布，但现实部署往往是用过去数据预测未来。对于规则会变化的政府采购，更应该设计时间外测试，例如：2023–2025 Train、2026 H1 Validation、2026 H2 Test。

时间切分不仅测试语言泛化，也会暴露法规变化和业务结构变化带来的 Concept Drift。

45. Validation 曲线如何识别过拟合

假设 1～4 个 Epoch 中 Train Loss 和 Validation Loss 都下降；从第 5 个 Epoch 开始 Train Loss 继续下降，但 Validation Loss 反而持续上升。此时最可能的解释是模型开始针对训练细节过拟合。

最佳 Checkpoint 往往在 Validation 表现最好的阶段，而不是最后一个 Epoch。这就是 Early Stopping 的直觉基础。

46. Shortcut Learning 的诊断问题：模型到底利用了什么信息？

模型表现好以后，不要只问“分数多少”，还要问“它为什么能答对”。可以把机构名替换、去掉模板页眉、同义改写关键条款、保留关键词但改变语义。如果性能剧烈变化，说明模型可能依赖表面 shortcut。

例如模型看到“投诉处理决定”几个字就预测高风险，并不能说明它学会风险原则。

47. Hard / Contrastive Cases 为什么能识别假理解

“措辞非常像但标签不同”和“标签相同但理由不同”的案例最能暴露决策边界。例如“必须在本市注册”和“必须在本市提供现场服务但不限制机构设立方式”表面都含“本市”，但业务含义不同。

如果模型两者都高风险，它可能只学关键词；如果能结合约束对象和履约必要性区分，才更接近稳定规律。

48. 泛化应该按多个 Slice 检查

至少可以按新项目、新年份、新地区、新行业、新采购方式、新措辞和边界案例切片。总体 90% 可能掩盖医疗技术参数只有 55% 的严重短板。

所以模型能力描述应该是“在哪些分布内经过验证”，而不是一句“支持政府采购”。

49. Error Analysis 分类表

错误至少可以拆成：漏掉风险、误报风险、风险类型错、依据错、事实理解错、上下文理解错、边界问题错、地区规则错、时间规则错、幻觉。不同错误对应完全不同的修复策略。

例如“风险判断正确但法规引用错误”主要是知识检索问题；“医疗领域整体弱”更像数据覆盖问题；“同义改写后崩溃”更像 shortcut 与表示问题。

50. 第二阶段小实验：该不该继续训练到第 10 个 Epoch

若 Epoch 3 时 Validation F1 达到 0.88，Epoch 4～10 Train F1 从 0.95 继续上升到 0.999，但 Validation F1 逐渐降到 0.78，那么继续训练并不是“更努力”，而是在强化训练集特有模式。应该保留最佳 Checkpoint，并调查过拟合原因。

1. 第三阶段总问题：模型到底“好”在哪里？

2. Confusion Matrix 四格

二分类的全部错误可以先拆成 TP、FP、FN、TN。

3. TP：真正风险被发现

这是我们希望系统捕获的正确报警。

4. FP：误报

模型报警但专家确认无明显风险。过多 FP 会造成审核疲劳。

5. FN：漏报

真正风险被模型放过。风险筛查场景里往往比 FP 更危险。

6. TN：正确放行

正常条款被正确判断为无明显风险。

7. 一个 1000 样本例子

设 TP=70、FP=10、FN=30、TN=890。下面所有指标都可由这四个数得到。

8. Accuracy

正确预测占全部样本比例。

公式 / 关键表达

Accuracy=(TP+TN)/(TP+TN+FP+FN)

9. 为什么 Accuracy 会骗人

95% 样本正常时，永远预测正常也有 95% Accuracy，但 Recall=0。

10. Baseline 必须一起看

任何漂亮分数都要和“永远预测多数类”“关键词规则”等最简单基线比较。

11. Precision：报得准不准

在模型报出的风险里，有多少是真的。

公式 / 关键表达

Precision=TP/(TP+FP)

12. Precision 的业务含义

Precision 低意味着专家被大量假报警淹没，最终可能产生 Alarm Fatigue。

13. Recall：找得全不全

在所有真实风险里，有多少被发现。

公式 / 关键表达

Recall=TP/(TP+FN)

14. 为什么第一道筛查通常优先 Recall

假阳性通常还能人工排除，而假阴性可能直接穿透审查流程。

15. 两阶段系统

第一阶段用高 Recall 扫描，第二阶段用更强模型、RAG、规则和专家提高 Precision。

16. Precision / Recall Trade-off

通常降低阈值会报更多风险：Recall 上升、Precision 下降；提高阈值则相反。

17. Threshold 不是默认 0.5

0.5 只是常见习惯，不是业务真理。阈值应该由成本、风险类型和校准决定。

18. 不同风险类型可以不同阈值

重大资格排他风险可以用更低阈值保障 Recall；低影响提示可用更高阈值减少噪声。

19. F1

Precision 和 Recall 的调和平均。

公式 / 关键表达

F1=2PR/(P+R)

20. 为什么 F1 不是终极指标

F1 默认同等看待 Precision 与 Recall，但业务未必如此。

21. Fβ

β>1 时更重视 Recall，例如 F2。

公式 / 关键表达

Fβ=(1+β²)PR/(β²P+R)

22. Micro F1

把所有样本整体统计，大类容易占主导。

23. Macro F1

先按类别计算再平均，更能暴露长尾类别。

24. Class Imbalance 再回看

类别极不均衡时，必须同时报告类别分布和多数类基线。

25. High-Risk Recall

重大风险可以单独设一条更严格指标，避免总体分数掩盖关键漏报。

26. Slice Evaluation

按风险类型、采购方式、行业、地区、项目类型、难度分别统计。

27. 平均值为什么会掩盖问题

总体 Recall 92%，医疗技术参数可能只有 58%。这对跨行业产品是严重风险。

28. 把指标翻译成业务语言

Recall 92% ≈ 每 100 个真实风险仍漏约 8 个；Precision 87% ≈ 每 100 个报警约 13 个是假警。

29. Expected Cost

把 FP/FN 乘以各自业务成本，可以把指标变成决策问题。

公式 / 关键表达

ExpectedCost=C_FN·FN + C_FP·FP

30. 指标服从业务目标

模型不是为了追求某个学术数字，而是管理不同错误类型的业务代价。

专家心智模型

核心心智模型：指标必须从业务风险倒推。

31. 法规依据也要有指标

除了风险判断，还需要 Citation Accuracy、Valid Citation Rate 等。

32. 解释和建议也要评估

Expert Correctness、Expert Acceptance、Suggestion Acceptance 可以衡量推理与建议质量。

33. 幻觉率

LLM 系统必须单独监控虚构法规、虚构案例、无依据断言。

34. 一个推荐的 ProcurementLM 指标树

风险发现用 Recall，误报控制用 Precision，分类用 Macro F1/F2，重大风险用 High-Risk Recall，依据用 Citation Accuracy，解释用专家评分，幻觉单独统计。

35. 第三阶段五个心智模型

错误有类型；Accuracy 会骗人；指标服从业务；Threshold 是业务决策；平均值掩盖弱 Slice。

36. 思维实验：两个模型怎么选

A: Recall 98%, Precision 45%；B: Recall 88%, Precision 90%。如果这是第一道高风险筛查，A 可能更适合第一层，但需要第二层去噪。

37. 第三阶段掌握标准

你应能从 Confusion Matrix 计算核心指标，并能根据业务代价解释为什么选择某个阈值。

38. 用 1000 个案例完整读一遍 Confusion Matrix

假设测试集中 TP=70、FP=10、FN=30、TN=890。总共 1000 条，其中真实风险 100 条。模型找出了 70 条，但漏掉 30 条；它一共报警 80 条，其中 10 条是误报。

这个四格表比单一 Accuracy 更接近真实业务，因为 FP 和 FN 造成的后果并不相同。

39. Accuracy 为什么会在类别不平衡时骗人

如果真实世界 95% 都是正常条款，模型永远预测“正常”，也有：

Accuracy=95% Accuracy=95\%

但：

Recall=0 Recall=0

对于风险筛查几乎没有价值。因此每次看到高 Accuracy，第一反应都应该检查类别分布和最简单 Baseline。

40. Precision：模型报出来的东西有多可信

Precision=TPTP+FP Precision=\frac{TP}{TP+FP}

在上面的例子中 Precision=70/80=87.5%。可以翻成业务语言：模型每报 100 个风险，大约 87～88 个是真的。如果 Precision 太低，专家会被大量假警报淹没，最终出现 Alarm Fatigue。

41. Recall：真实风险到底找回了多少

Recall=TPTP+FN Recall=\frac{TP}{TP+FN}

上例 Recall=70/100=70%。翻成业务语言：每 100 个真实风险中，模型漏掉约 30 个。对政府采购首轮合规扫描，Recall 往往比 Accuracy 更值得优先关注。

42. 为什么很多风险系统采用“两阶段架构”

第一阶段使用较低阈值、高 Recall，宁可多报一些候选；第二阶段再使用更强模型、RAG、规则和上下文提高 Precision。这样把“找全”和“判断准”拆成两个不同子问题。

这比要求一个模型一次同时实现极高 Recall 与极高 Precision 更容易工程化。

43. Threshold 不是模型内部真理，而是业务策略

模型输出连续风险分数 pp。真正形成分类决策时还需要阈值 TT：

Decision=𝟙[p≥T] Decision=\mathbb{1}[p\ge T]

降低 T 通常会提高 Recall、降低 Precision；提高 T 通常相反。默认 0.5 只是一种方便，不是政府采购业务自动正确的阈值。

44. 不同风险类型可以使用不同阈值

高代价风险，例如严重资格限制，可以设置更低阈值追求高 Recall；低影响提示则可以更强调 Precision。阈值策略应该与错误成本连接，而不是全系统只有一个数字。

45. F1 与 Fβ

F1 是 Precision 与 Recall 的调和平均：

F1=2PRP+R F1=2\frac{PR}{P+R}

如果业务更重视 Recall，可以用：

Fβ=(1+β2)PRβ2P+R,β>1 F_\beta=(1+\beta^2)\frac{PR}{\beta^2P+R},\quad \beta>1

例如 F2 会比 F1 更重视 Recall。但 F2 仍只是代理指标，不能替代真正业务成本。

46. Macro 与 Micro：长尾风险类型为什么更适合看 Macro

Micro 指标把所有样本合在一起计算，高频类别主导结果；Macro 则先计算每个类别，再平均。若资格条件有三万条、罕见程序风险只有几百条，Micro 可能掩盖长尾类别完全不会的问题。

47. Slice Evaluation：平均值是最容易骗人的数字之一

政府采购可以按严重程度、采购方式、货物/服务/工程、行业、地区、年份、难度、Hard Negative/Positive 等切片。总体 F1=0.90 不足以支持“模型可靠”，必须知道最差 Slice 在哪里。

48. 把模型指标翻译成专家能理解的业务语言

Recall 92% 更直观的表达是：每 100 个真实风险大约漏 8 个。Precision 87% 则是：每 100 个报警大约有 13 个需要人工排除。业务团队只有理解这种后果，才能正确选择阈值。

49. Expected Cost：把 FP 与 FN 放进同一决策框架

ExpectedCost=CFN⋅FN+CFP⋅FP ExpectedCost=C_{FN}\cdot FN+C_{FP}\cdot FP

如果一个严重漏报的平均成本远高于一次人工误报复核，那么即使 F1 略低，高 Recall 策略仍可能更合理。最终优化的是错误成本，而不是数学指标本身。

50. ProcurementLM 的指标树

风险发现看 Recall；误报控制看 Precision；多风险类型看 Macro F1/F2；重大风险单独看 High-Risk Recall；法规依据看 Citation Accuracy / Valid Citation Rate；理由看 Expert Correctness；修改建议看 Expert Acceptance；生成模型还要看 Hallucination Rate。

  1. 错误有不同类型，FP 与 FN 不能混成一个“错”。
  2. Accuracy 会被类别分布欺骗，必须检查 Baseline。
  3. 指标服从业务目标，不是业务服从指标。
  4. Threshold 是业务决策层，而不是模型固定常数。
  5. 平均值会掩盖局部弱点，必须做 Slice Evaluation。

1. 第四阶段总链路

这一阶段把“预测分数如何变成 Loss，再变成参数更新”完整串起来。

公式 / 关键表达

X → z → Sigmoid → p → Cross Entropy → Loss → Gradient → 参数更新

2. 为什么模型不直接输出 0/1

如果只有硬分类，训练无法区分“差一点错”和“极其自信地错”。连续分数提供更细反馈。

3. Logit z

线性模型先产生一个不受限制的原始分数。

公式 / 关键表达

z=wᵀX+b

4. Logit 的直觉

z 很大为正时倾向风险，z 很大为负时倾向正常，z≈0 时模型犹豫。

5. Sigmoid

把任意实数压到 0～1。

公式 / 关键表达

σ(z)=1/(1+e^{-z})

6. Sigmoid 数值直觉

z=-5≈0.007，-2≈0.12，0=0.5，2≈0.88，5≈0.993。

7. Logistic Regression

把线性 logit 与 Sigmoid 结合，得到二分类概率分数。

公式 / 关键表达

P(Y=1|X)=σ(wᵀX+b)

8. 概率分数不等于真实概率

模型输出 0.82 不自动意味着现实有 82% 概率存在风险；是否能这样解释要看 Calibration。

9. Binary Cross Entropy

二分类常用交叉熵衡量概率预测。

公式 / 关键表达

L=−[y log p +(1−y)log(1−p)]

10. 当 y=1

Loss 简化为 −log p。预测越接近 1，Loss 越小。

公式 / 关键表达

y=1 ⇒ L=−log p

11. 当 y=0

Loss 简化为 −log(1−p)。预测越接近 0，Loss 越小。

公式 / 关键表达

y=0 ⇒ L=−log(1−p)

12. 自信地错会被重罚

真实 y=1 时，p=.99→Loss≈.01，p=.5→.693，p=.2→1.609，p=.01→4.605。

13. Cross Entropy 的核心直觉

它不断推动正确答案的概率质量上升，并强烈惩罚高置信度错误。

14. Loss 的“几何形状”

不同 Loss 对不同错误的惩罚方式不同，因此 Loss 本身就是我们对模型学习方向的设计。

15. Gradient

∂L/∂w 表示参数轻微变化对 Loss 的影响方向和敏感度。

16. Gradient Descent

沿 Loss 下降方向更新参数。

公式 / 关键表达

w_new=w_old−η∂L/∂w

17. BCE + Sigmoid 的漂亮结果

对 logit 的导数非常简洁。

公式 / 关键表达

∂L/∂z=p−y

18. 当 y=1,p=.2

p−y=-.8，说明需要强烈把 z 往上推。

19. 当 y=1,p=.95

p−y=-.05，只需小幅修正。

20. 当 y=0,p=.9

p−y=.9，说明模型高置信度错，需要强烈把 z 往下推。

21. 线性权重的梯度

如果 z=wᵀx+b，则每个权重梯度包含对应输入特征。

公式 / 关键表达

∂L/∂w_i=(p−y)x_i

22. 这就是 Credit Assignment 的起点

最终错误信号如何分配回每个参数，是后面 Backprop 的核心问题。

23. Forward Pass

输入从前往后经过模型得到预测。

24. Backward Pass

从 Loss 反向计算各层参数梯度。

25. Backpropagation

反向传播不是“把答案传回去”，而是高效应用链式法则计算梯度。

26. Optimizer

梯度给方向，Optimizer 决定如何利用当前与历史梯度更新参数。

27. Learning Rate 再理解

η 是每次参数移动尺度。过大振荡/发散，过小收敛缓慢。

28. Loss 与 Metric 不同

Loss 是可微训练目标；Recall/F1 等 Metric 是业务评估指标，通常不能直接拿来反向传播。

29. 业务重视 Recall 怎么办

可以通过 Class Weight、Focal Loss、采样、阈值、Cost-sensitive 设计让训练更接近业务目标。

30. Score 与 Decision 分离

模型负责输出连续 Score；业务层通过 Threshold 与策略把 Score 变成行动。

公式 / 关键表达

X → Score/Probability → Threshold → Decision

31. 为什么不同风险可以不同 Threshold

高代价 FN 的风险类型可以用更宽松阈值保障召回。

32. Confidence ≠ Truth

模型越自信不代表越接近现实；这将在第 11 阶段进入 Calibration 与不确定性。

模型把“项目地点在本市”判 0.99 风险，说明它可能学了关键词捷径；Cross Entropy 会在正确标签下强烈纠正这类错误。

为什么比 p=.51 错得更值得关注？因为它既带来更大 Cross Entropy，也暴露模型内部可能存在非常确定的错误规律。

37. 第四阶段掌握标准

你应能解释 Logit、Sigmoid、Cross Entropy、Gradient、Forward/Backward、Optimizer，以及 Loss 与 Metric 的区别。

38. 为什么不让模型直接输出 0 或 1

如果模型只输出硬分类，我们无法区分“差一点错”和“非常自信地错”。连续分数让训练系统知道错误程度，也允许后续使用不同 Threshold。

最简单二分类模型先计算 Logit：

z=wTX+b z=w^TX+b

再用 Sigmoid 映射到 0～1：

p=σ(z)=11+e−z p=\sigma(z)=\frac{1}{1+e^{-z}}

39. Sigmoid 数值直觉

z p
-5 ≈0.007
-2 ≈0.12
0 0.50
2 ≈0.88
5 ≈0.993

z=0 表示模型处于边界；z 大幅为正或负表示模型把样本推向某一侧。这个 p 是模型分数，不自动等于真实世界经过校准的客观概率。

40. Binary Cross Entropy 为什么适合概率分类

L=−[ylogp+(1−y)log(1−p)] L=-[y\log p+(1-y)\log(1-p)]

当 y=1 时，Loss=-log p。预测 0.99 的 Loss 约 0.01，预测 0.5 是 0.693，预测 0.2 是 1.609，预测 0.01 达到约 4.605。它会特别重罚“非常自信地答错”。

41. Cross Entropy 的核心直觉：把概率质量推向正确答案

Loss 并不要求模型先形成我们理解的法律概念，它只是让正确标签的概率变高、错误标签的概率变低。模型内部最终形成什么表示，是大量这种压力共同作用的结果。

42. 最漂亮的一条导数：Sigmoid + BCE 得到 p-y

对于二分类：

∂L∂z=p−y \frac{\partial L}{\partial z}=p-y

若真实 y=1、模型 p=0.2，则误差信号为 -0.8，更新压力很强；若 p=0.95，则只有 -0.05，说明已经接近正确方向，不需要大改。

43. 误差信号如何进一步传给权重

在线性模型中：

∂L∂wi=(p−y)xi \frac{\partial L}{\partial w_i}=(p-y)x_i

这就是 Credit Assignment 的最小版本：最终错误会沿计算图向后分配到对结果有贡献的参数。深层神经网络的 Backpropagation 本质上把同样思想扩展到很多层。

44. Forward、Backward、Optimizer 三者不要混淆

Forward：用当前参数从 X 算到预测；Backward：从 Loss 往回计算梯度；Optimizer：根据梯度和自己的更新规则真正修改参数。

可以用类比：Gradient 是坡度方向，Optimizer 是走路策略，Learning Rate 是步长。

45. Loss 与 Metric 为什么可以不同

训练需要可微 Loss，因此常用 Cross Entropy；业务评估可能更关心 Recall、F2、High-Risk Recall。可以通过 Class Weight、Focal Loss、Sampling、Threshold 和成本敏感策略，让训练目标更贴近业务指标。

46. Score 与 Decision 必须分离

完整链路应该是：

X→Score→Threshold→Decision X\rightarrow Score\rightarrow Threshold\rightarrow Decision

这意味着同一模型可以在不同业务流程使用不同 Decision Policy，不必为了每个阈值重新训练模型。

47. Confidence ≠ Truth

模型输出 0.82 不自动意味着“现实世界有 82% 概率违规”。是否可以把模型概率当成现实概率，需要额外做 Calibration。这个提醒会在第 11 阶段发展成完整的概率校准与选择性预测体系。

2. Dataset

训练集是很多 (x,y) 样本的集合。

D={(x₁,y₁),…,(x_N,y_N)}

3. Batch

一次前向/反向通常只取一小批样本，而不是整个数据集。

4. 为什么不用 Batch=1

单样本梯度噪声很大，更新方向容易受偶然样本影响。

5. 为什么不用 Full Batch

整个数据集一起算虽然稳定，但内存和计算代价极大，更新也太慢。

6. Mini-batch 是折中

小批量梯度可以看成对全数据梯度的随机估计。

MiniBatchGradient ≈ FullDatasetGradient

每个 Batch 只代表数据世界的一小部分，所以梯度会波动。

8. 一个 Batch 内发生什么

Forward → 样本 Loss → Batch 平均 Loss → Backward → Optimizer Update。

9. Optimizer Step

真正修改参数的一次动作。注意它和“做了一次 forward/backward”不一定一一对应，因为可能有梯度累积。

10. Epoch

完整看过一遍训练集叫一个 Epoch。

心智模型②：Epoch 是训练深度，不是能力。

21. AdamW

Transformer/LLM 中常见，采用解耦 Weight Decay。

心智模型③：不要把梯度和优化器混为一谈。

23. Micro Batch

单张 GPU 一次真正放进显存的样本数。

显存放不下目标 Batch 时，可以连续计算多个 micro-batch 的梯度，累积后再做一次 optimizer step。

29. Shuffle 与 Split 不同

先按项目/时间做 Train/Val/Test 隔离，再在 Train 内 shuffle。不能用 shuffle 破坏隔离。

30. 训练是随机优化

不同 Batch 带来不同梯度，所以 Loss 曲线轻微抖动是正常的。

心智模型④：看趋势，不要把每一个 step 的波动都当故障。

如果训练 5 个 Epoch，理论上约经历 10,000 次 Batch；若没有梯度累积，每个 Batch 通常对应一次 Optimizer Step。

48. Batch 为什么是“局部民意调查”

Full Batch 使用整个训练集计算精确梯度，但计算和显存成本巨大；Batch=1 梯度噪声很大。Mini-Batch 折中：用一小批样本估计总体梯度。

MiniBatchGradient≈FullDatasetGradient MiniBatchGradient\approx FullDatasetGradient

由于每批样本不同，Loss 曲线轻微抖动是正常现象。

49. Epoch 不是能力分数

一个 Epoch 只表示训练数据整体被看过一遍。多看几遍可能学得更充分，也可能强化记忆和过拟合。真正选择训练深度需要观察 Validation，而不是迷信“3 Epoch”“10 Epoch”这样的固定经验数字。

50. Learning Rate 的三种典型失败

LR 太大：Loss 剧烈振荡甚至爆炸；LR 太小：训练非常慢，看起来几乎不学习；合理 LR：能够稳定下降并逐渐细化。现代 Transformer 常使用 Warmup + Decay：开始小步稳定进入训练，后期减小步长精修。

51. Parameter 与 Hyperparameter

Parameter 是训练自动学的权重；Hyperparameter 是训练前由工程师设置的策略，例如 Learning Rate、Batch Size、Epoch、Weight Decay、Warmup Ratio、LoRA Rank。不要把二者混为一谈。

52. SGD、Momentum、Adam、AdamW 的高层区别

SGD 直接按当前梯度走；Momentum 带有历史方向；Adam 根据梯度一阶、二阶统计量为不同参数自适应步长；AdamW 在 Transformer/LLM 训练中很常见，并把 Weight Decay 处理方式与 Adam 更清楚地分离。

第一课不要求推导优化器公式，但要建立：Gradient 给信息，Optimizer 决定怎样使用信息。

53. Gradient Accumulation：显存小也能模拟更大有效 Batch

若单卡只能放 Micro Batch=4，而希望 Effective Batch=32，可以累积 8 次梯度后再更新一次参数。

多 GPU 时：

EffectiveBatch=PerDeviceBatch×NumGPUs×GradientAccumulation EffectiveBatch=PerDeviceBatch\times NumGPUs\times GradientAccumulation

例如 4 GPU × 每卡 2 × Accumulation 8 = 64。

54. Micro-Batch 次数不等于 Optimizer Step

梯度累积期间会多次 Forward/Backward，但参数尚未改变；只有执行 Optimizer Step 时参数才更新。这一点在计算总训练步数、Scheduler 和日志时非常重要。

55. Shuffle 与 Split 是两个完全不同的问题

Split 决定哪些项目属于 Train/Val/Test，必须先防止泄漏；Shuffle 只是训练集内部每个 Epoch 重新打乱顺序，使 Batch 更接近整体分布。不能用“我已经 Shuffle 了”来证明没有项目级泄漏。

一条 100 Token 的资格条款和一条 8000 Token 的完整采购需求，在显存、计算和有效上下文上完全不同。政府采购文件从短公告到数百页投标文件跨度极大，因此还要关注 Tokens per Batch、Context Length、Chunking 与 Packing。

Loss = w1·L_risk + w0·L_normal

16. Cost-sensitive Learning

当 FN 业务代价更高时，可以在 Loss、采样和阈值多层体现这种代价。

17. 样本频率就是隐形权重

某种模式出现 10000 次，另一种 100 次，即使单样本 Loss 相同，总梯度影响也不同。

专家心智模型

心智模型②：Sampling 本身就是训练策略。

18. Hard Example

模型已经会的简单样本边际价值低；最难案例更能推动能力边界。

19. Hard Negative

看起来像风险但其实不应该直接判风险，用来打掉过度报警。

政府采购案例 / 例子

“项目需要在本市提供2小时应急服务，但不要求供应商预设本地机构。”

20. Hard Positive

看起来措辞正常，实际上可能存在限制，需要减少漏报。

政府采购案例 / 例子

“为确保质量，供应商须具有连续十年以上同类项目经验。”是否合理必须看必要性与竞争影响。

21. Decision Boundary

Hard Example 往往位于分类边界附近，最能修正边界。

22. Contrastive Pair

相似措辞、不同标签，让模型学习真正差异。

23. 高置信度错误特别值钱

模型 p=.01 但真实 y=1，说明内部存在非常确定的错误规律。

24. Hard Negative Mining

上线模型从大量数据中筛出“高置信风险但专家确认无风险”的案例，作为下一轮难负样本。

25. Hard Positive Mining

寻找“模型高置信无风险但专家确认有风险”的漏报。

26. Error Bank

把真实错误结构化沉淀为长期资产：模型版本、置信度、错误类型、根因、专家修正。

27. 模型帮助我们找数据

V0 告诉你它最不会什么，数据团队去补这些区域，再训练 V1。

公式 / 关键表达

Model → Error → Data → Better Model

28. Duplicate

原始 10 万条不代表 10 万条独立信息。重复模板会让某些模式被过度加权。

29. Exact Dedup

去除完全相同文本。

30. Near Dedup

去除只改数字、名称或少量措辞的近重复。

31. Semantic Dedup

语义高度相似但表面不同的样本也要控制比例。

32. Raw Count ≠ Effective Data

真正有价值的是新增信息量、覆盖和多样性。

33. Long Tail

低频风险类别样本少，但不一定不重要，甚至可能更复杂。

34. 长尾处理

专项采集、Oversampling、Class Weight、RAG、Rules 或专项模型都可以用。

35. Curriculum Learning

像课程一样组织数据：基础→普通→对比→边界→争议。

36. Level 1：明显案例

先学清晰模式，建立基础分界。

37. Level 2：上下文案例

加入项目需求、采购标的、履约背景。

38. Level 3：对比案例

同词不同结论、同结论不同表达。

39. Level 4：边界案例

专家需要认真分析，训练模型处理灰区。

40. Level 5：争议案例

保留专家分歧和不确定性，而不是强压成伪确定标签。

41. Dataset 是课程，不是仓库

你在设计一个学生接受什么教育，而不是只在堆文件。

专家心智模型

心智模型③：Dataset Design = Curriculum Design。

42. Active Learning

专家时间昂贵，应优先标模型最犹豫、模型/规则冲突或高置信度错误的样本。

43. Information Gain

下一条数据的价值取决于它能提供多少新信息，而不是它是否“又多一条”。

44. 专家时间是稀缺资源

目标不是标最多数据，而是每一小时专家标注带来最大模型提升。

45. Data Quality Control

检查输入完整性、标签正确性、专家一致性、依据有效性、时间有效性、重复、难度和泄漏。

46. 时间元数据

法规、政策和案例随时间变化，应保存 case_date、effective_date、expiry_date、jurisdiction 等。

47. 时间也是 X 的一部分

同一句话在不同时间、地区和制度背景下可能答案不同。

48. Label / Target Leakage

输入中如果已经包含“财政部门认定该条款不合理”，模型可以直接抄答案。

49. Future Leakage

发布前预测风险时不能把后续更正、投诉处理或中标结果放进输入。

50. 六层数据质量金字塔

原始数据→清洗→结构化→专家标注→困难数据→真实错误闭环数据。

51. 真正的护城河

公开原始文件不难复制，专家标注、难例和真实错误闭环才是高价值资产。

52. 第六阶段五个心智模型

训练数据是模型世界；样本频率是隐形权重；困难样本决定边界；高置信错误是宝藏；Dataset 是课程。

53. 阶段掌握标准

你应能用 Coverage、Balance、Difficulty、Label Quality、Deployment Match 五个维度比较两个数据集，而不是只看样本数。

54. Dataset 不是世界，而是从世界抽出来的一份样本

训练数据来自经验分布 P̂\hat P，真实部署来自 PrealP_{real}。理想状态是二者足够接近，但政府采购会随地区、行业、政策和时间变化，因此 IID 只能被视为近似假设。

Ptrain(X,Y)≈Pdeploy(X,Y) P_{train}(X,Y)\approx P_{deploy}(X,Y)

数据量巨大但覆盖单一，仍然可能离真实部署很远。

55. 建立政府采购数据覆盖矩阵

未来至少按“风险类型 × 采购类别 × 采购方式 × 地区 × 时间 × 严重度 × 难度”统计。十万条数据不能只报总数，还应该知道医疗 Hard Negative 有多少、工程边界案例有多少、新政策后的案例有多少。

这类 Coverage Dashboard 比单纯文件计数更接近模型真实教育经历。

56. 类别不平衡与隐形奖励

若 95% 样本是正常，5% 是风险，模型频繁看到多数类，等价于多数类对总梯度拥有更大影响。因此样本频率本身就是一种 Implicit Weight。

解决办法包括 Oversampling、Undersampling、Class Weight、Focal Loss 或重新设计 Batch 采样，但不能机械追求 50/50；最终训练分布要服务于业务成本和部署环境。

57. Oversampling 与 Undersampling 的代价

Oversampling 风险类能增强学习信号，但过度重复可能导致过拟合；Undersampling 多数类能快速平衡，但可能丢掉大量有价值的正常模式。更成熟的策略是保留多样性，同时控制每类在 Batch 中出现的频率。

58. Class Weight：不改数量，也可以改错误代价

可以让风险样本 Loss 权重大于正常样本：

L=w1Lrisk+w0Lnormal L=w_1L_{risk}+w_0L_{normal}

如果漏报代价高，设置 w1>w0w_1>w_0 能让模型更重视风险类错误。但最终效果仍需 Validation 验证。

59. Hard Negative：最能打掉“关键词=风险”的假理解

Hard Negative 是“看起来非常像风险，但真实并非如此”的正常案例。例如“项目需要在本市提供 2 小时应急服务，但不要求供应商提前设立本地机构，可通过驻场或合作服务满足”。

如果模型只是看到“本市”和“2小时”就报警，Hard Negative 会迫使它学习约束对象、履约必要性和竞争影响。

60. Hard Positive：看起来正常但真正危险

例如“为确保服务质量，供应商须具有连续十年以上同类项目经验”。措辞很合理，但“十年”是否必要、是否与履约能力相关、是否造成不必要竞争限制，需要更深入判断。

Hard Positive 能防止模型被“为了保证质量”等合理化语言麻痹。

61. High-Confidence Wrong 是最宝贵的一类错误

模型 p=0.49、真实 y=1 只是边界犹豫；模型 p=0.01、真实 y=1 则说明它建立了非常确定但错误的内部规律。后者通常具有更高 Information Gain，应优先进入专家复核与训练集。

未来 Error Bank 应记录 model_confidence、root_cause、difficulty、domain 和 expert_review_status。

62. Hard Negative Mining：让模型自己暴露下一批最值得标的数据

当前模型先扫描大量未标注数据，找出高置信报警；专家确认其中哪些其实正常，这些就是 Hard Negative。下一轮训练专门修复这些盲区。

Model→Error→ExpertCorrection→NewData→BetterModel Model\rightarrow Error\rightarrow ExpertCorrection\rightarrow NewData\rightarrow BetterModel

比随机下载更多 PDF 更高效。

63. Duplicate：十万条不等于十万条信息

如果同一模板只改公司名和数字出现两万次，Raw Count 很大但 Effective Data 很小，而且某种模式会被反复强化。去重要分 Exact Dedup、Near Dedup 和 Semantic Dedup。

去重也不能机械删除所有相似句，因为某些 Minimal Pair 正是我们故意保留的对比信息。

64. Long Tail：低频不代表低价值

程序性特殊风险、罕见行业或新政策案例可能一年只出现少量，但一旦发生业务代价很高。可以通过专项采集、Oversampling、权重、RAG、规则引擎或专项模型处理，不应让 Overall Accuracy 掩盖长尾失效。

65. Curriculum Learning：数据是一套课程，不是一堆文件

可以从明显案例开始，再加入普通上下文、对比案例、边界案例和专家争议案例。现代 LLM 训练不一定严格按“先易后难”顺序，也可能混合采样，但 Curriculum 的核心思想仍然是主动设计学习经历。

66. Contrastive Pair：边界信息比重复简单样本更有价值

“必须在本市设立分公司”与“要求在本市提供现场服务但不限制注册地”表面相似，却对应不同判断逻辑。把它们成对出现，模型必须解释差异，远比重复 100 次同一个明显风险句更有信息量。

67. Active Learning：把有限专家时间花在最有信息量的数据上

有 100 万条未标注数据、专家只能标 1 万条时，可以优先选择模型最犹豫、模型与规则冲突、多模型分歧、高置信度疑似错误或关键长尾领域的案例。

政府采购项目里真正昂贵的通常不是 GPU，而是高水平专家标注时间。

68. 时间元数据必须进入数据设计

法规会生效、废止、替代。训练数据至少应考虑 case_date、effective_date、expiry_date、jurisdiction、status。否则模型可能把过去正确、现在失效的规则当成永久知识。

同一句条款在不同时间和地区可能对应不同 Y，因此时间和地区本身也可能属于 X。

69. Target / Future Leakage：输入里不能偷偷藏答案

如果任务是在采购文件发布时预测风险，输入却包含后续投诉决定、更正公告或最终处理结果，模型离线成绩会虚高。要始终问：线上做出判断的那个时刻，这条信息真的已经存在吗？

70. 六层数据质量金字塔

L1 原始文件；L2 清洗数据；L3 结构化数据；L4 专家标注；L5 Hard/Contrastive 数据；L6 真实模型错误 + 专家纠正。越往上数量可能越少，但单位训练价值往往越高。

公开原始文件容易复制，真正形成长期护城河的是 L4～L6。

71. 第六阶段五个核心心智模型

  1. 训练数据只是世界的样本，不是世界本身。
  2. 样本频率就是隐形权重，采样本身就是训练策略。
  3. 困难样本决定决策边界，简单重复样本边际价值会下降。
  4. 高置信度错误暴露最深的错误规律，是高价值训练资产。
  5. Dataset 是课程设计：应该主动决定模型看什么、看多少、以什么对比方式看。

重点包括 Data Bias、Label Noise、Distribution Shift、OOD、Data Contamination、Shortcut Learning、Error Taxonomy 与 Root Cause Analysis。

1. 第七阶段总问题：模型表现差，到底改哪里？

错误可能来自 Data、Label、Split、Distribution、Model、Optimization、Deployment。专家先诊断，再优化。

公式 / 关键表达

Diagnosis before Optimization

2. 一个错误现象可能有多个原因

“医疗技术参数漏报”可能是医疗数据少、标签错、分布漂移、模型容量不足或解析问题，不能从现象直接跳到结论。

3. Data Bias

训练数据本身偏向某些项目类型、行业、地区或时间，模型会继承这种经验偏差。

4. Coverage 比总量更重要

10 万条数据如果 70% 是 IT，也不能代表整个政府采购世界。

5. Sampling Bias

采集机制使样本不是现实总体的代表。

6. 投诉案例采样偏差

如果风险样本几乎都来自投诉决定，模型可能学会投诉文件风格，而不是一般采购文件中的风险规律。

7. Representation Bias

中央/省级文件多、基层县级少，模型可能对基层语言与业务结构陌生。

8. Model Envelope

专业描述模型能力时，要说明“在哪些分布内经过验证”，而不是笼统说“支持政府采购”。

专家心智模型

心智模型①：模型永远有经验边界。

9. Label Bias

Y 本身可能系统性偏差。错误标签会产生错误梯度。

10. Label Noise

专家误标、边界模糊、数据录入错误都会形成噪声。

11. 专家分歧

不同专家对“5个同类业绩”可能有不同判断，说明任务本身带不确定性。

12. 不要把分歧硬压成 0/1

可以保存 expert_votes、ambiguity、confidence 等字段。

13. Adjudication

模型与标签冲突时应复核：模型错、专家错、还是案例本身有争议。

14. Ground Truth 不是绝对真理

专业标签是当前专家体系对现实的最佳测量。

专家心智模型

心智模型②：Label 也是测量结果。

15. Distribution Shift

训练分布和部署分布不同。

16. Covariate Shift

P(X) 变了，但 P(Y|X) 大致不变。例：IT 比例下降、医疗比例上升。

17. Label Shift

P(Y) 变了。例：行业规范后真实风险比例明显下降。

18. Concept Drift

P(Y|X) 变了。例：新法规改变同一条款的适用结论。

19. 时间维度是政府采购核心风险

规则会更新，模型必须知道“什么时候有效”。

20. 法规元数据

document_id、jurisdiction、publish/effective/expiry date、status、supersedes 等应进入知识系统。

21. 模型是分布快照

训练好模型可以看成某一时刻 P_train 的 Snapshot。现实持续变化，因此必须监控。

专家心智模型

心智模型③：模型不是永久有效。

22. OOD：Out-of-Distribution

新输入远离训练分布时，模型缺少直接经验。

23. 流畅回答不代表 In Distribution

LLM 在 OOD 上也可能非常流畅甚至高置信度。

24. Abstention

可靠系统应在低置信、OOD、证据不足时拒绝给确定结论或转人工。

25. Selective Prediction

只自动处理模型足够可靠的一部分问题。

26. 专业 AI 的能力边界意识

会判断 + 会怀疑 + 会拒答，比“什么都敢回答”更适合高风险领域。

专家心智模型

心智模型④：知道自己不会也是能力。

27. Data Contamination

Test 内容已经进入 Train，导致离线成绩虚高。

28. Exact Duplicate 污染

完全相同样本同时出现在 Train/Test。

29. Near Duplicate 污染

只换数字、名称或同义改写，也可能造成严重泄漏。

30. Project Leakage

同一项目不同文件分到 Train/Test，项目身份和答案相互泄漏。

31. Template Leakage

同一家代理机构大量高度一致模板随机拆分，会把模板记忆当成泛化。

32. Institution Leakage

采购人/代理机构身份本身可能成为捷径，应设计跨机构评测。

33. Future Leakage

用后续投诉、更正、中标信息预测发布时风险，是“用未来预测过去”。

34. False Confidence

污染最大的危害是让团队误以为模型已经足够好。

35. Spurious Correlation

模型利用业务上不正确、但训练数据里好用的特征。

36. Counterfactual Test

只改变关键词或关键条件，看模型判断是否按业务逻辑变化。

37. Perturbation Test

保持语义基本不变，改写表达。如果性能暴跌，说明表面词汇依赖严重。

38. Train/Val 第一层诊断

Train差+Val差：欠拟合/数据/优化；Train好+Val差：过拟合/分布差；Val好+线上差：漂移/污染/Serving skew。

39. Slice Evaluation 第二层诊断

总体 90% → 技术参数 68% → 医疗技术 52% → 边界案例 37%，逐层定位错误区域。

40. Confidence × Correctness

高置信度错误是最高优先级；低置信度错误更多是模型诚实地犹豫。

41. 人工错误归因

输入缺信息、标签错、法规过期、知识缺失、语义理解错、复杂推理错、OOD、长上下文丢失等。

先知道错误来自哪里，再决定加数据、修标签、加 RAG、换模型还是改训练。

43. 模块化诊断

Parser→Risk Detector→Classifier→Retriever→Reasoner→Citation Validator→Suggestion Generator，最终错时要能定位层级。

44. Error Taxonomy

系统错误必须可归因，而不是“AI 有时就是会错”。

专家心智模型

心智模型⑤：先诊断再优化。

45. Controlled Experiment

一次主要改一个变量，才能知道提升来自哪里。

提出“医疗表现差是数据覆盖不足”假设→补医疗数据→重新评测→验证或否定。

47. 诊断案例：医疗技术参数

若资格 Recall 90%、评分82%、技术42%，再查训练分布发现医疗技术只有700条，优先补 Coverage，而不是立即换70B。

模型有经验边界；标签是测量；模型是分布快照；可靠系统要能拒答；先诊断再优化。

50. 阶段掌握标准

看到线上掉点时，你应先问错误集中在哪里、Train/Val 是否正常、分布/标签/污染/OOD/Drift 哪一层最可疑。

51. 三种 Distribution Shift 再做一次严格区分

Covariate Shift：P(X)P(X) 变了，例如 IT 项目从 70% 变成医疗项目 60%，但同一 X 的判定机制大致没变。Label Shift：P(Y)P(Y) 变了，例如行业规范后风险条款占比从 20% 降到 5%。Concept Drift：P(Y|X)P(Y|X) 变了，例如新规实施后同一做法对应的合规结论改变。

三者修复方式不同：Covariate 更偏覆盖与采样；Label Shift 可能需要重新调阈值；Concept Drift 往往需要更新知识、规则、标签甚至重新训练。

52. OOD 最大的危险：模型不一定知道自己没见过

流畅输出并不能证明样本在训练分布内。一个几乎没见过特殊科研设备的模型，仍可能非常自信地生成完整理由。成熟系统应该把 OOD Score、领域覆盖和证据充分性放进决策策略，必要时 Abstain。

53. 专业系统的 Abstention 不是失败，而是能力边界管理

可靠输出可以是：“当前项目与训练/案例库常见项目差异较大；缺少专项市场数据和足够相似案例；当前置信度低，建议专家复核。”

Predict+EstimateUncertainty+DetectOOD+Abstain Predict+EstimateUncertainty+DetectOOD+Abstain

比“什么都敢判”更适合高影响专业场景。

54. Data Contamination 的三个层次

Exact Duplicate：Test 原句出现在 Train；Near Duplicate：只换措辞或数字；Project Leakage：同一采购项目的其他文书进入 Train。还可能有 Template Leakage、机构泄漏和 Future Leakage。

污染最危险之处不是分数高，而是制造 False Confidence，让团队误以为模型已具备上线能力。

55. Counterfactual / Perturbation Test 用来找 Shortcut

保持语义基本不变只换措辞，如果预测大变，说明模型过度依赖表面词汇；保留关键词但改变语义，如果预测不变，说明模型可能没有理解上下文。

例如“注册资本不得低于5000万元”和“采购文件不得以注册资本作为不合理限制条件”都含“注册资本”，但业务方向相反。

56. 四层 Diagnosis 工作流

第一层看 Train/Validation；第二层做 Slice Evaluation；第三层看 Confidence × Correctness，优先 High-Confidence Wrong；第四层让专家对错误做 Root Cause 标注。

只有把错误定位到具体 Slice 和根因，才能决定下一步是加数据、修标签、加 RAG、改 Parser、换模型还是调训练。

57. 一个完整医疗技术参数诊断案例

线上客户反馈医疗项目漏报多。总体 Recall 91% 并不能否认问题。先切医疗 Recall=61%；再切资格 90%、评分 82%、技术参数 42%；再查训练集发现医疗技术参数只有 700/20,000。

错误集中于专用设备兼容性、临床场景和市场替代信息。此时主要根因是 Data Coverage，而不是 Model Capacity。补充医疗 Normal/Hard Positive/Hard Negative 和专家案例后再评测，才是诊断驱动训练。

58. 模块化诊断：最终答案错不等于 LLM 本身错

生产系统可以拆为 Document Parser → Risk Detector → Classifier → Retriever → Reasoner → Citation Validator → Suggestion Generator。若风险判断正确但法律依据错，应优先修 Retriever/法规 Metadata，而不是继续 Fine-tune 风险分类器。

59. Error Taxonomy 应该成为结构化资产

至少保存 error_type、root_cause、domain、difficulty、confidence、ood_score、label_review、recommended_action。这样“模型错了”才能转化为下一轮具体的数据和实验计划。

60. Controlled Experiment：一次不要同时改十件事

若一次同时换模型、加数据、改 LR、改 Prompt、换 Loss、加 RAG，即使 F1 提高，也不知道哪个因素有效。成熟研发使用 Hypothesis → Experiment → Measurement → Diagnosis → Next Hypothesis。

  3. 模型是某一时刻训练分布的 Snapshot，现实会 Drift。
  4. 可靠系统必须知道什么时候不应该自动回答。
  5. 先诊断再优化，Error Analysis 往往比盲目 Scale 更重要。

57. Dataset Card 应该描述“这版数据是谁”

除了样本数，还要记录来源、时间范围、地区、任务、标签 Schema、正负比例、Hard Examples、去重方法、专家标注指南版本、Train/Val/Test 划分和已知缺陷。Dataset v1.3 不是“比 v1.2 多 3000 条”这么简单。

58. Label Schema 与 Annotation Guideline 也必须版本化

从 0/1 二分类升级到低/中/高风险，已经改变了任务；专家规则从“本地要求一律高风险”升级到“区分注册地限制和履约服务必要性”，也改变了标签含义。

如果把不同标准的数据混在一起却不记录版本，模型会看到系统性 Label Drift。

59. Random Seed 为什么要记录，但不能迷信

同一代码也有 Shuffle、初始化、Dropout 等随机性。Seed 能提高复现程度，但不同 GPU/CUDA/并行算法仍可能造成差异。重要实验最好跑多个 Seed，并报告 Mean ± Std，而不是只展示最高一次。

60. Checkpoint 需要保存什么

为了恢复训练，完整 Checkpoint 不只包含 Model Weights，还可能包含 Optimizer State、Scheduler State、Global Step 和 Random State。只恢复权重却让 AdamW 的内部状态清零，训练轨迹会发生变化。

61. Best Checkpoint 不一定是 Last Checkpoint

若 step 3000 Validation F1=0.89，step 5000 只有 0.83，最终发布模型应该来自 3000，而不是因为它“更新”就选最后一个。Model Registry 应明确记录最佳 Checkpoint 来源。

62. Experiment Tracking 记录的是证据链

Experiment ID 应关联 Dataset、Base Model、Git Commit、Config、Seed、LR、Batch、训练时间、Loss 曲线、Metrics、Best Checkpoint 和 Error Analysis。TensorBoard、MLflow、Weights & Biases 只是不同实现，核心都是让实验可比较、可追溯。

63. Model Registry 是生产模型的档案馆

模型可以经历 Development → Candidate → Staging → Production → Archived。每个注册版本应有训练实验、评测集、核心指标、Known Limitations 和使用范围，不能把一个随机 checkpoint 直接复制到服务器就叫“上线”。

64. Model Lineage：从生产结果一路追回原始数据

RawData→CleanDataset→ExpertLabels→TrainDataset→Experiment→Checkpoint→ProductionModel RawData\rightarrow CleanDataset\rightarrow ExpertLabels\rightarrow TrainDataset\rightarrow Experiment\rightarrow Checkpoint\rightarrow ProductionModel

政府采购合规系统尤其需要这种 Traceability：争议发生时，应能回答当时是哪版模型、哪版法规库和哪版规则产生结果。

65. Immutable Artifact 原则

发布后的 dataset_v1.2 不应该原地偷偷修 100 条仍叫 v1.2；应生成 v1.3。Gold Test 同样应该冻结，确需升级则创建新版本。否则同一个版本名代表不同内容，实验比较失去意义。

66. Regression Test 与 Quality Gate

新模型总体分数提高，也可能把某一核心能力修坏。发布门禁应检查资格、技术、评分、Hard Negative、高风险、跨地区等固定 Slice；只有满足 High-Risk Recall、总体 Recall、Precision 和无严重回归等条件，Candidate 才能进入 Production。

67. Model Card 是模型说明书

至少描述 Purpose、Training Dataset、Evaluation Set、核心指标、Known Strengths、Known Weaknesses、Out of Scope 和 Recommended Use。专业表述不是“支持所有政府采购”，而是明确在哪些年份、领域和任务上经过验证。

61. “模型给 0.92”到底能不能读成“92%概率有风险”

不能自动这样解释。0.92 首先只是当前模型在当前分布下的输出分数。只有经过 Calibration，并且确认当前数据与校准集足够相似，才更有资格把它当成近似现实概率使用。

62. 一个直观 Calibration 例子

从历史预测中找 100 个分数约 0.8 的案例。如果长期真实正类比例也约 80%，模型在这个区间校准较好；如果真实只有 55%，说明明显 Overconfidence。

Accuracy 高与 Calibration 好是两个独立维度。

63. Reliability Diagram、ECE 与 Brier Score

Reliability Diagram 比较每个置信度桶的平均预测与真实发生率；ECE 把这些偏差汇总成一个校准误差；Brier Score 计算概率预测的平方误差。它们都在回答分类 Accuracy 无法回答的问题：概率值本身是否可信。

64. Aleatoric 与 Epistemic Uncertainty

Aleatoric：问题本身或现有事实就存在不可约不确定性，例如缺少市场供应数据，专家也无法唯一判断。Epistemic：模型知识不足，例如从未见过某特殊设备领域；补数据、知识或模型可能降低。

诊断不确定性时必须先问：缺的是模型能力，还是现实信息？

65. Selective Prediction：模型不需要每题都自动回答

模型可以只处理自己最可靠的 70%，剩下 30% 转人工。若这 70% Accuracy=97%，对政府采购可能比 100% 自动化但 Accuracy=85% 更有价值。

核心 Trade-off 是 Coverage 与 Risk。

66. Risk-Coverage Curve

随着自动化门槛提高，Coverage 通常下降、自动处理错误率下降。业务可以明确选择：例如自动 60% 但 Critical Error<1%，而不是追求 100% 自动处理。

这让“自动化率”从宣传数字变成可治理的风险参数。

67. System Confidence 不等于 Model Probability

本身就是被某个“选择机制”影响后的结果。

29. 第五个核心心智模型：数据不是“现实”，而是现实经过一个采集机制后的样本

可以写成：

Reality→SelectionProcess→Dataset \boxed{ Reality \rightarrow SelectionProcess \rightarrow Dataset }

所以做数据集时必须问：

哪些数据永远不会被我看到？

例如：

没有发生投诉但实际存在隐性风险的项目

可能特别难收集。

这意味着：

你的数据可能系统性缺失重要样本。

30. 这与 Missing Not At Random 有关系

如果数据缺失是完全随机的：

问题相对简单。

但很多现实数据是：

MNAR

Missing Not At Random。

缺失本身有规律。

例如：

高质量内部专家纠错案例往往不公开。

于是公开数据里：

复杂边界案例可能严重不足。

这就是现实数据的结构性偏差。

31. 怎么让模型少依赖 Spurious Correlation？第一种：数据多样化

让同一个表面特征出现在：

不同标签里。

例如：

含“本市” + 风险
含“本市” + 无风险

这样“本市”本身就不再是一个完美捷径。

模型被迫学习：

上下文。

32. 第二种：Contrastive Data

专门构造：

相似X 相似X

但：

不同Y 不同Y

例如：

A

必须在本市注册。

风险高。

B

项目服务地点在本市。

无明显风险。

这种对比能打掉：

关键词捷径。

33. 第三种：Counterfactual Augmentation

人为构造反事实样本。

例如原句：

“供应商必须具有10年成立历史。”

风险。

反事实：

“供应商须具备完成本项目所需的履约能力，并提供相应证明。”

更合理。

模型被训练：

不是“年限”本身，而是条件与履约需求关系。

34. 第四种：多环境训练

例如把数据明确拆成：

Environment 1：IT
Environment 2：医疗
Environment 3：物业
Environment 4：工程

看：

哪些规律在所有环境都稳定？

如果一个特征：

某特定模板词

只在 IT 有效，

但医疗完全没用，

很可能是脆弱特征。

而：

“条件是否与履约能力相关”

如果多个领域都有效，

更可能具有稳定性。

35. 这就接近 Domain Generalization

领域泛化

目标不是：

在已见领域做到最高分。

而是：

在未见领域也尽可能保持能力 \boxed{ 在未见领域也尽可能保持能力 }

例如：

Train：

  • IT
  • 物业
  • 教育

Test：

医疗。

这种测试比：

同行业随机切分

更能检查模型是不是学到稳定规律。

38. 什么叫 Invariant Risk Minimization 的思想？

不需要掌握算法细节。

只需要理解它背后的愿望：

找那些在多个环境里都有效的预测规律。

而不是：

在某一个环境里把 Loss 降到最低。

也就是说：

StableAcrossEnvironments>BestOnOneEnvironment \boxed{ Stable\ Across\ Environments > Best\ On\ One\ Environment }

这对政府采购模型非常适合。

42. 因果与解释性也有关系

假设模型告诉你：

“这条风险高，因为出现了‘本地’。”

这可能只是：

Feature Attribution。

不一定是：

因果解释。

例如 SHAP 告诉你：

“本市”这个词对模型预测影响很大。

只能说明：

模型依赖它 模型依赖它

这是很重要的区别：

ModelExplanation≠CausalExplanation \boxed{ Model\ Explanation \neq Causal\ Explanation }

43. 解释模型为什么这样预测，不等于解释现实为什么这样发生

答案：

因为“注册资本”token 权重很大。

这是：

Model Explanation

而：

可能是：

因为它与履约能力缺乏合理关联并限制潜在供应商。

这是：

Domain / Causal Explanation

两者完全不同。
