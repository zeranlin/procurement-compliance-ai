A. 本阶段核心心智模型（前置）

  1. MoreGPUs ≠ LinearSpeedup。
  2. ScaleUp ≠ ScaleOut。模型分片和多副本服务是两种不同扩展。
  3. Tensor Parallel 用高频通信换取单层并行。
  4. Pipeline Parallel 的关键是 Stage Balance，而不是层数平均。
  5. 单副本放不下才优先考虑 Sharding；放得下但吞吐不够优先考虑 Replica。

B. 中文释义增强：本阶段重要英文工程术语

一、先区分三种常见扩展方式

Tensor Parallel

张量并行

把同一层里的大矩阵运算：

横向切到多张 GPU。

Pipeline Parallel

流水线并行

把不同 Layer：

纵向分到不同 GPU / Stage。

Replica Serving

多副本服务

每组 GPU：

放一份完整模型，由负载均衡器把不同请求分发给不同副本。

所以：

ScaleUp≠ScaleOut \boxed{ ScaleUp \neq ScaleOut }

前两者是把一个模型拆开，

Replica 更像把完整服务复制多份。

二、Tensor Parallel

大矩阵 WW 可以被切到：

GPU0
GPU1
GPU2
GPU3

各自计算部分结果，再通过：

All-Reduce
All-Gather
Reduce-Scatter

等通信组合。

所以：

TPGain=ParallelCompute−CommunicationCost \boxed{ TPGain = ParallelCompute - CommunicationCost }

因此高速互联非常重要。

三、核心心智模型 ①

Interconnect 属于模型推理性能的一部分

同样四张 GPU，

如果互联带宽不同，

TP 性能可能差很多。

所以：

4GPUs≠4GPUs \boxed{ 4GPUs \neq 4GPUs }

真正硬件描述要包括：

GPU型号
单机卡数
显存
GPU互联
节点网络
NUMA

四、TP Degree 为什么不是越大越好？

TP Degree 增大：

每卡Weight减少
计算更分散

但也会：

通信更多
同步更多
Kernel更碎

所以：

TPDegree存在最优区间 \boxed{ TPDegree 存在最优区间 }

五、Pipeline Parallel

例如：

GPU0：Layer 1-10
GPU1：Layer 11-20
GPU2：Layer 21-30
GPU3：Layer 31-40

数据依次穿过 Stage。

因此：

PP=LayerPartitioning \boxed{ PP = LayerPartitioning }

但如果某个 Stage 特别慢，

其他 Stage 就会等待。

这形成：

Pipeline Bubble

流水线气泡

所以：

PipelineBalance决定PPEfficiency \boxed{ PipelineBalance 决定 PPEfficiency }

六、核心心智模型 ②

EqualLayerCount 不一定等于 EqualWork

不同 Layer 的：

算力
显存
KV
通信

可能不同。

所以 Pipeline 切分不能只按层数平均。

七、Replica Serving

如果模型本身已经能放进一组 GPU，

但总流量太大，

可以：

Replica A
Replica B
Replica C

每个副本各自服务请求。

这时扩的是：

总吞吐。

所以：

ModelDoesNotFit→Sharding \boxed{ ModelDoesNotFit \rightarrow Sharding }

ModelFitsButTrafficHigh→Replication \boxed{ ModelFitsButTrafficHigh \rightarrow Replication }

八、核心心智模型 ③

先问“放不下”还是“吞吐不够”

Parallelism Choice 必须由 Bottleneck Type 决定。

盲目提高 TP：

可能增加通信，却没有解决真正问题。

可以：

×
3 Replicas

TP + PP

发布

越复杂。

所以：

MoreParallelism=MoreCoordination \boxed{ MoreParallelism = MoreCoordination }

十、多节点为什么更难？

跨节点：

延迟更高
带宽更低
故障点更多

对于通信密集型 TP，

网络可能直接成为瓶颈。

所以：

Topology必须进入ParallelPlan \boxed{ Topology 必须进入 ParallelPlan }

十一、Latency 和 Throughput 要分开评

TP：

可能改变单请求延迟。

Replica：

主要提升总吞吐。

PP：

让更大模型可部署，但可能带来流水线延迟。

所以：

Parallelism必须分别评Latency和Throughput \boxed{ Parallelism 必须分别评 Latency 和 Throughput }

十二、Fault Domain

如果一个服务实例由很多 GPU 共同组成，

任意一张卡故障：

可能让整个实例不可用。

所以：

LargerShardGroup可能扩大FailureImpact \boxed{ LargerShardGroup 可能扩大 FailureImpact }

性能拓扑：

同时也是可靠性拓扑。

十五、本阶段最重要的 8 个核心心智模型

① MoreGPUs ≠ LinearSpeedup。

② ScaleUp ≠ ScaleOut。模型分片和多副本服务是两种不同扩展。

③ Tensor Parallel 用高频通信换取单层并行。

④ Pipeline Parallel 的关键是 Stage Balance，而不是层数平均。

⑤ 单副本放不下才优先考虑 Sharding；放得下但吞吐不够优先考虑 Replica。

⑥ Parallelism Choice 必须由 Bottleneck 与 Hardware Topology 共同决定。

⑦ 4GPUs ≠ 4GPUs，互联拓扑会改变真实性能。

⑧ 性能拓扑同时也是故障拓扑。
