Serving Architecture：把 Model + RAG + Agent 接成真实 API 服务

模型能启动，不代表系统能上线。怎样把 Gateway、Model Server、Retriever、Agent、Tool、State、Queue、Auth 和 Trace 真正接成生产服务？

A. 本阶段核心心智模型（前置）

  1. Deployment ≠ ModelLoading。
  2. ProductionAI = ModelSystem + DistributedSystem。
  3. Traceability 从统一 Request ID 开始。
  4. AgentControlPlane ≠ ModelExecutionPlane。
  5. Decision ≠ Authorization。

B. 中文释义增强：本阶段重要英文工程术语

英文工程表达 中文工程 / 业务含义
Agent Agent/智能体：基于状态、工具和策略循环执行多步任务的系统
RAG RAG/检索增强生成：推理时先检索外部证据再生成
State 状态：保存任务进度、事实和待办
Serving 服务化：把模型包装成可扩展、可观测、可治理的在线服务
Idempotency 幂等：重复执行不会产生不可控重复副作用
Observability 可观测性：通过指标、日志、追踪理解系统内部状态

日志再多，

六、RAG Service

RAG 可以独立：

Retriever

独立扩容
独立版本化
独立回滚

RAGVersion≠ModelVersion \boxed{ RAGVersion \neq ModelVersion }

七、Agent Orchestrator

它负责：

Goal
Plan
Tool Routing
State
Retry
Human Escalation
Completion

而 Model Server：

所以：

AgentControlPlane≠ModelExecutionPlane \boxed{ AgentControlPlane \neq ModelExecutionPlane }

八、Tool Service

工具可能：

查预算
写数据库
提交审批
发送消息

所以必须有：

权限
超时
幂等
审计
重试策略

模型可以决定：

想调用什么。

但系统策略决定：

能不能调用。

所以：

Decision≠Authorization \boxed{ Decision \neq Authorization }

九、Timeout Budget

整个请求：

应有总超时预算。

内部组件：

RAG
Model
Tool
Database

也要有分层 Timeout。

否则一个依赖卡住：

整条链都会无限等待。

十、Retry 与 Idempotency

读请求：

通常更容易安全重试。

写请求：

可能产生重复副作用。

所以：

RetryPolicy必须感知Idempotency \boxed{ RetryPolicy 必须感知 Idempotency }

十一、Circuit Breaker

如果某个依赖持续失败，

继续调用会放大故障。

所以：

Circuit Breaker

熔断器

在达到阈值时：

暂停调用、降级或转人工。

十二、核心心智模型 ③

RetryEverything 会把局部故障变成雪崩

成熟 Retry 必须考虑：

上限
Backoff
Jitter
Idempotency
Circuit Breaker

十三、Backpressure

下游模型满载时，

上游不能无限灌请求。

需要：

Backpressure

背压

可以通过：

限流
排队
降级
拒绝

保护下游。

十四、业务 State 不能只存在 Prompt 里

真实状态应该存：

Database
Durable Store
State Service

模型上下文只是：

Working Context

工作上下文

所以：

BusinessState≠PromptMemory \boxed{ BusinessState \neq PromptMemory }

十五、Streaming 与 Cancellation

流式服务还要处理：

连接保持
客户端取消
断线
中途超时

如果用户取消：

后端应该尽快停止 Decode。

所以：

ClientCancellation→ComputeCancellation \boxed{ ClientCancellation \rightarrow ComputeCancellation }

十六、Observability 与 Privacy

更多日志：

更容易排障。

但也带来：

隐私
敏感数据
留存
访问风险

因此：

Observability必须和Privacy一起设计 \boxed{ Observability 必须和 Privacy 一起设计 }
