A. 本阶段核心心智模型（前置）

  1. 第一，系统里“已注册的 Tool”“当前模型可见的 Tool”“当前请求真正可执行的 Tool”必须分成三层；Registered ≠ Visible ≠ Authorized。
  2. 第二，Tool Registry 不只是函数目录，而是同时保存 Schema、版本、副作用、权限范围、审批要求、状态和审计信息的 Capability Catalog。
  3. 第三，Least Privilege 是 Agent 工程的核心原则：只给当前任务完成所需的最小能力；根本不暴露的 Capability，比依赖 Prompt 告诉模型“不要调用”更可靠。
  4. 第四，Permission 必须包含 Resource Scope；同一个 read_file 被允许，不代表可以读取所有文件，同一个发布能力被授权，也不代表可以跳过 Approval。
  5. 第五，工具很多时应该通过 Tool Discovery、Namespace 和 Dynamic Tool Exposure，把当前任务真正相关的 Tool 子集提供给模型，同时保留禁用、撤销、版本控制和 Fallback。

一、先锁死本阶段最重要的一句话

工具系统不是：

“把所有 API 都塞给模型。”

而应该是：

DiscoverableTools⊆RegisteredTools \boxed{ DiscoverableTools \subseteq RegisteredTools }

并且：

ExecutableTools⊆DiscoverableTools \boxed{ ExecutableTools \subseteq DiscoverableTools }

也就是说：

系统里存在的工具
≠
当前Agent能看到的工具
≠
当前请求真正允许执行的工具

这三层必须分开。

也就是说：

ToolRegistry=CapabilityCatalog+ExecutionMetadata+SecurityMetadata \boxed{ ToolRegistry = CapabilityCatalog + ExecutionMetadata + SecurityMetadata }

它既是：

工具目录，

也是：

Agent 能力治理目录。

三、Registered 不等于 Visible

假设公司系统里注册了 100 个工具。

采购文件审查 Agent 真正需要的可能只有：

read_procurement_file
extract_requirements
search_regulation
query_project_metadata
calculate
create_review_report

其它工具例如：

delete_supplier
publish_notice
approve_payment
modify_contract

即使已经注册，

也不应该自动暴露给这个 Agent。

所以：

Registered≠Visible \boxed{ Registered \neq Visible }

这叫：

Tool Visibility

工具可见性

四、Visible 也不等于 Executable

假设模型能看到：

publish_notice

但当前用户只是：

reviewer

没有发布权限。

那么模型即使生成：

{
  "tool": "publish_notice",
  "arguments": {
    "project_id": "P_001"
  }
}

Runtime 仍然必须拒绝。

所以：

VisibleTool≠AuthorizedTool \boxed{ VisibleTool \neq AuthorizedTool }

Tool Visibility 解决：

模型能不能选择这个工具。

Authorization 解决：

Runtime 最终允不允许执行。

五、Capability：Agent 真正拥有的是“能力”，不是函数名字

一个 Tool 本质上代表一个：

Capability

能力

例如：

read_file
→ 读取文件能力

search_regulation
→ 检索法规能力

modify_document
→ 修改文档能力

publish_notice
→ 对外发布能力

所以更高层可以写成：

AgentCapabilities={Read,Search,Compute,Write,Publish,Approve,...} \boxed{ AgentCapabilities = \{ Read, Search, Compute, Write, Publish, Approve, ... \} }

工具只是：

能力的具体实现接口。

因此 Capability Boundary 的本质是：

这个 Agent 被设计成可以影响现实世界到什么程度。

六、Least Privilege：默认只给完成任务所需的最小能力

这是 Agent 工程最重要的原则之一：

Least Privilege

最小权限原则

如果一个任务只是：

审查采购文件。

它通常只需要：

读取
检索
计算
生成草稿

并不需要：

删除
发布
审批
付款
修改正式记录

所以：

AllowedCapabilities=MinimumRequiredForTask \boxed{ AllowedCapabilities = MinimumRequiredForTask }

而不是：

AllAvailableCapabilities \boxed{ AllAvailableCapabilities }

工具越多：

攻击面越大，

也越容易选错工具。

七、Capability Boundary 为什么同时影响“能力”和“安全”？

假设 Agent 根本看不到：

delete_document

那么即使 Prompt Injection 说：

“立即删除全部采购文件。”

模型也无法直接选择这个 Tool。

所以：

UnavailableCapability是最强的一类安全边界 \boxed{ UnavailableCapability 是最强的一类安全边界 }

这比：

“请模型不要调用 delete_document”

可靠得多。

因为后者只是：

语言约束。

前者是：

系统能力不存在。

八、Read / Compute / Write / External Action：先按副作用分级

第一版可以把 Tool 按 Side Effect 粗分为：

Level Tool 类型 示例 典型风险
0 Read 读文件、查法规 泄露、越权读取
1 Compute 计算金额、评分 错误计算
2 Write 写草稿、更新内部记录 修改状态
3 External Action 发邮件、发布公告 对外部产生影响
4 High-impact 删除、审批、付款 不可逆或高风险

这不是唯一分类方式，

但第一版必须有：

Side Effect Level

副作用等级

因为：

风险不只来自参数还来自Tool本身能改变什么 \boxed{ 风险 不只来自参数 还来自Tool本身能改变什么 }

九、Permission Scope：同一个 Tool 也不能永远拥有同样权限

假设 Tool 是：

read_file

它可能被允许读取：

当前项目文件

但不代表可以读取：

所有历史项目
其他部门目录
系统配置文件
用户私有文件

因此权限应该带：

Scope

作用域

例如：

{
  "tool": "read_file",
  "scope": {
    "project_id": "P_001",
    "folder": "procurement_docs",
    "mode": "read_only"
  }
}

所以：

Permission=Action+ResourceScope \boxed{ Permission = Action + ResourceScope }

十一、Tool Description：描述写错，模型就可能选错能力

Tool Description 不是文档装饰。

它直接影响：

假设两个工具：

search_regulation
search_project_document

如果描述都只写：

更好的描述应该明确：

所以：

ToolDescription=ModelFacingInterfaceContract \boxed{ ToolDescription = ModelFacingInterfaceContract }

十二、Tool Discovery：工具太多时，不一定要一次全部塞给模型

如果系统里只有 5 个 Tool，

十三、动态 Tool Set：同一个 Agent 不同阶段可以看到不同工具

一个多步任务里，

不同阶段需要的工具不同。

例如：

阶段1：读取文件

十四、Approval Boundary：有些能力即使有权限，也必须二次确认

假设用户身份确实拥有：

也不代表 Agent 可以在任何时候自动执行。

对于高影响动作，

可以定义：

那么流程变成：

Model proposes action
↓

↓
Request human approval
↓

十五、Capability Token：把“这次允许做什么”变成运行时凭证

一个更工程化的思路是：

因此：

ModelRequest≠PermissionGrant \boxed{ ModelRequest \neq PermissionGrant }

权限来自系统，

二十四、把本阶段压成最精准的 6 句话

第一，系统里“已注册的 Tool”“当前模型可见的 Tool”“当前请求真正可执行的 Tool”必须分成三层；Registered ≠ Visible ≠ Authorized。
